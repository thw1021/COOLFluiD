# 第 9 章 使用流程与输入文件格式

本章把"跑一个算例"这件事拆到底：总体流程与最小模板（9.1）、CFcase 文件语法（9.2）、全量字段参考（9.3）、网格格式与转换（9.4）、运行方式（串行/并行/重启动，9.5）、集群作业脚本（9.6）。所有机制均以 `apps/Solver/coolfluid-solver.cxx`、`src/Config/`、`src/Environment/CFEnv.cxx`、`src/Framework/Simulator.cxx`、`src/Framework/ConvergenceMethod.cxx` 源码及本仓库实测算例（`plugins/Burgers/testcases/`）为准。

## 9.1 总体使用流程

### 9.1.1 五步法

| 步骤 | 动作 | 产物 | 参考 |
|------|------|------|------|
| 1 | 准备网格 | `*.CFmesh`（或外部格式 + 转换，见 9.4） | 9.4、第 7 章各算例 |
| 2 | 编写 CFcase | `*.CFcase`（纯文本，键值对） | 9.2、9.3 |
| 3 | 运行求解器 | `coolfluid-solver --scase x.CFcase` | 9.5 |
| 4 | 监控收敛 | `P0-output.log`、`convergence.plt.<NS>` | 9.5.4、10.1.5 |
| 5 | 后处理 | `.plt/.vtu` 可视化、派生量提取 | 第 10 章 |

### 9.1.2 程序启动时序

`coolfluid-solver` 的启动时序（实测 `main()`）：

```
命令行解析 (AppOptions)
   │
   ▼
CFEnv::initiate  → 并行环境初始化 (PE::InitPE) + 模块装载
   │
   ▼
ConfigFileReader 解析 CFcase → ConfigArgs（键→值字典）
   │
   ▼
CFEnv::configure + setup  → 环境键（CFEnv.*）、日志、文件访问后端
   │
   ▼
创建 Maestro（默认 SimpleMaestro；CFcase 中 Simulator.Maestro 可换）
   │
   ▼
创建 Simulator → openCaseFile → 解析 SubSystems/SubSystemTypes
   │
   ▼
maestro->call_signal("control", ...)  → 编排各 SubSystem 循环
   │
   ▼
SimulationStatus 记录最终残差 →（可选）--residual 回归比对 → 退出
```

要点：

- **两阶段配置**：`CFEnv` 先吃一遍 `ConfigArgs`（环境键），然后 `Simulator` 带着整个文件再吃一遍（各对象按自己的嵌套名取键）——同一份文件被不同对象各取所需；
- **解析与实例化分离**：CFcase 只声明 `PhysicalModelType/SpaceMethod/…` 的**名字字符串**，实际对象在 configure 阶段由 `FactoryRegistry` 按名创建（第 6.3.1 节）；
- **并行启动**：MPI 下每个 rank 独立执行相同流程，`PE` 层负责全局同步（`SetBarrier`）。

### 9.1.3 最小可用 CFcase 模板（逐行讲解）

以 `plugins/Burgers/testcases/burgersFVM.CFcase` 注释版为蓝本（实测可跑通，见第 7.2.1 节）：

```
### Residual = -5.00048764                       # 元注释：作者标定的目标残差（供 --residual 回归）
Simulator.Modules.Libs = libCFmeshFileWriter \   # 续行符拼接多行值
  libCFmeshFileReader libTecplotWriter \ ...
Simulator.Paths.WorkingDir = plugins/Burgers/testcases/   # 工作目录（相对 --bdir）
Simulator.Paths.ResultsDir = ./                            # 结果输出目录
Simulator.SubSystem.Default.PhysicalModelType = Burgers2D  # Default 前缀：模型实例名
Simulator.SubSystem.Burgers2D.refValues = 1.0              # 物理参数（模型实例名.键）
Simulator.SubSystem.OutputFormat = Tecplot CFmesh          # 输出格式列表
Simulator.SubSystem.Tecplot.FileName = burgersFVM.plt      # 各格式的键
Simulator.SubSystem.StopCondition = Norm                   # 收敛判据选择
Simulator.SubSystem.Norm.valueNorm = -5.0                  # 判据参数
Simulator.SubSystem.Default.listTRS = SuperInlet FaceSouth FaceWest FaceNorth  # 面名清单
Simulator.SubSystem.MeshCreator = CFmeshFileReader         # 网格读取器（注册名）
Simulator.SubSystem.CFmeshFileReader.Data.FileName = burgers.CFmesh
Simulator.SubSystem.ConvergenceMethod = FwdEuler           # 时间推进（注册名）
Simulator.SubSystem.FwdEuler.Data.CFL.Value = 0.5
Simulator.SubSystem.SpaceMethod = CellCenterFVM            # 空间方法（注册名）
Simulator.SubSystem.CellCenterFVM.Data.FluxSplitter = Roe  # 方法.Data.键
Simulator.SubSystem.CellCenterFVM.BcComds = SuperInletFVMCC SuperInletFVMCC \  # 命令表
  SuperInletFVMCC SuperOutletFVMCC
Simulator.SubSystem.CellCenterFVM.BcNames = East South West North               # 命令实例名
Simulator.SubSystem.CellCenterFVM.East.applyTRS = SuperInlet                   # 实例.键
Simulator.SubSystem.CellCenterFVM.East.Def = 1.5                                # 命令参数
```

模式总结：**对象层级名 = 注册名**，命令表用 `Comds/Names` 声明实例，实例参数用 `实例名.键` 直接挂在方法名下。

## 9.2 CFcase 文件语法

### 9.2.1 词法元素（`src/Config/NestedConfigFileReader.cxx` 实测）

| 元素 | 写法 | 行为 |
|------|------|------|
| 键值分隔符 | `=` | `label = value`，两侧空白自动裁剪 |
| 追加赋值 | `+=` | `label += value`：把新值以空格追加到已解析值之后（首次出现等同 `=`） |
| 注释 | `#` 开头 | 从 `#` 到行尾全部剥离（弱剥离：字符串内部含 `#` 也会被切，源码自述 warning） |
| 元注释 | `###` | 特殊指令前缀；**`### IncludeCase <文件>` 递归包含另一个 CFcase**（可嵌套） |
| 块注释 | `!#` … `#!` | 跨行块注释，可中途关闭 |
| 续行符 | 行尾 `\` | 行尾反斜杠将下一行拼接（可连续多行；拼接时裁掉尾空白） |
| HOME 展开 | 值/路径首字符 `~` | 展开为 `$HOME` |
| XML 自动识别 | 文件首行 `<?xml` | 自动切换到 XML 解析器（`XMLConfigFileReader`；用于 conf 与旧式文件） |

### 9.2.2 键与值

- **键**：点分路径 `Simulator.SubSystem.CellCenterFVM.Data.FluxSplitter`；大小写敏感；标签内不允许空格；
- **重复定义**：同一 label 第二次以 `=` 赋值直接抛 `BadMatchException("Overriding previously specified option for: …")`——所以**模板继承用 `### IncludeCase` 而不是复制粘贴**；
- **值类型**（由键的注册类型决定，`addConfigOption<T>`）：

| 类型 | 写法示例 | 说明 |
|------|----------|------|
| bool | `true/false`（或 `1/0`） | 字符串转布尔 |
| CFuint / CFreal | `200`、`-5.5`、`1e-4` | 整数/浮点 |
| string | `burgers.CFmesh` | 原样字符串 |
| vector\<T\> | `libA libB libC`、`refValues = 1.0 1.0 1.0 2.5` | **空格分隔**序列（`addConfigOption<std::vector<…>>`；`refValues` 也是普通 vector，实测全部 CFcase 均用空格分隔） |

> ⚠️ **已删除的旧版错误行**：旧表曾把 `refValues` 列为"元组 `(p,T,vx,vy)`（括号+逗号）"。经实测：**代码与全部 CFcase 中不存在括号逗号元组语法**（`src/Config/ConfigFileReader.cxx` 无括号解析），`refValues` 就是空格分隔的 vector；且 2D 顺序应为 **`(p,u,v,T)`**（见 `bluntbody-start.CFcase` 行内注释 `#p u v T`），旧示例 `(p,T,vx,vy)` 顺序亦错。CFcase 里的圆括号只出现在注释或 `if(...)`/`min(...)`/`max(...)` 等**函数表达式**中。

| 表达式串 | `1.5-2.*x`、`if(i<100,20.,…)` | 函数定义类键接收可解析数学表达式（`Def/Vars` 族） |

### 9.2.3 层级与匹配规则（`src/Config/OptionList.cxx` 实测）

1. 每个 `ConfigObject` 注册的选项自动获得**嵌套前缀**：`getNestName() + "."`（`ConfigObject::configure` 中 `setHierarchyOptions(basename)`）；
2. 匹配是**嵌套标签匹配**：CFcase 中的键只要与某选项的完整嵌套名**尾部一致**即命中——所以 `Simulator.SubSystem.NewtonIterator.Data.CFL.Value` 也可以写成（若唯一）更短的 `NewtonIterator.Data.CFL.Value`；
3. **歧义即报错**：`findMatches` 命中多个选项时 `complainAboutMatches` 抛出歧义异常——缩写虽合法，但请谨慎；
4. **未消费键**：任何对象没消费掉的键留在 `ConfigArgs` 中；`CFEnv.ErrorOnUnusedConfig = true` 会将其作为错误（默认关闭，仅告警）——调试"键拼错没生效"的**第一开关**；
5. 同名异构：不同子系统的方法同名实例靠**方法名前缀**区分（如 `SubSysA.FluxReconstruction.…` vs `SubSysB.FluxReconstruction.…`）。

### 9.2.4 多值列表与命令表

- **向量键**：空格分隔（`Simulator.Modules.Libs = libA libB`、`Default.listTRS = FaceA FaceB`）；
- **命令表**（如 `BcComds/BcNames`、`InitComds/InitNames`、`SetupCom/SetupNames`）：两个空格分隔的**等长向量**，按位置配对——第 i 个命令注册名配第 i 个实例名；
- **空值**：`键 =`（无值）对 string 得空串、对 bool 报错——填整不要留空；
- **`### IncludeCase` 继承**：被包含文件的键在包含文件键**之前**解析，后写覆盖（`=`）或追加（`+=`）。

### 9.3.3 停止条件全表（`src/Framework/StopCondition` 各 provider 实测）

| 注册名 | 参数键 | 用途 |
|--------|--------|------|
| `Norm` | `valueNorm`（动态） | 残差（log10）降到目标值即停，如 `valueNorm = -5.0`（**最常用**） |
| `AbsoluteNormAndMaxIter` | `AbsNorm`、`MaxIter`（均动态） | 绝对残差 + 最大迭代双条件 |
| `RelativeNormAndMaxIter` | `RelativeNorm`、`MaxIter`、`Warn` | 相对残差（相对首步）+ 最大迭代；`Warn` 控制到 MaxIter 时告警 |
| `MaxNumberSteps` | `nbSteps`（**vector，每个 Namespace 一个条目**） | 固定迭代步数，如 `MaxNumberSteps.nbSteps = 100`；多 Namespace 时写 `100 200` |
| `MaxTimeNumberSteps` | `maxTime`（动态，CFreal） | 物理时间推进到 `maxTime` 停止（非定常，`MaxTimeNumberStepsCondition.cxx` 实测） |
| `NormAndMaxSubIter` | `Norm`、`MaxSubIter`、`Namespace` | 耦合子迭代场景：指定 Namespace 的残差判据 |
| `RelativeNormAndMaxSubIter` | `RelativeNorm`、`MaxSubIter`、`InterfaceName`、`TRSName`、`DataType`、`Namespace` | 耦合界面残差判据（对接计算） |
| `AeroCoef` | `ConvCL/ConvCD/ConvCM`、`CheckCL/CheckCD/CheckCM`、`NbIters`、`MaxIter` | 气动系数收敛判据（`plugins/AeroCoef/AeroCoefStopCondition.cxx`） |

多判据组合通过 `GlobalStopCriteria`（`StopCondition = GlobalMaxNumberSteps` 等）在 `src/Framework/` 中实现；多数算例只需 `Norm` 或 `MaxNumberSteps`。

### 9.3.5 物理模型参数

物理模型以**实例名**为前缀挂键（第 3 章），通用模式：

```
Simulator.SubSystem.Default.PhysicalModelType = NavierStokes2D   # 默认实例 = Default
Simulator.SubSystem.NavierStokes2D.refValues = 1.0 1.0 1.0 2.5  # 参考量（空格分隔 vector，2D 顺序为 p,u,v,T）
Simulator.SubSystem.NavierStokes2D.refLength = 1.0               # 参考长度（雷诺数定义用）
Simulator.SubSystem.NavierStokes2D.Reynolds = 1000.              # 雷诺数（供无量纲输运系数）
Simulator.SubSystem.NavierStokes2D.machInf = 0.85                # 来流马赫数（供远场 BC）
Simulator.SubSystem.NavierStokes2D.tempRef = 288.15              # 参考温度
```

各 `PhysicalModelType` 的完整参数表见第 3 章与第 4 章对应节（如 NEQ 多温度模型的 `MixtureFrozen/Equilibrium` 切换键）。

### 9.3.6 收敛方法参数（`ConvergenceMethod` 家族）

| 键 | 示例 | 说明 |
|----|------|------|
| `NewtonIterator.Data.CFL.ComputeCFL` | `Function` / `Interactive` | CFL 数来源：函数 / 交互文件 |
| `NewtonIterator.Data.CFL.Function.Def` | 分段函数表达式 | 如 `if(i<100,1.,5.)`（`Def` 族接受自由表达式，实测） |
| `NewtonIterator.Data.CFL.Interactive.CFL` | `1` | 交互模式初始 CFL（`.inter` 文件运行期改写，9.3.10） |
| `NewtonIterator.Data.MaxSteps` | `2000` | 外层 Newton 循环步数上限（vector，`NewtonIteratorData.cxx:37` 实测） |
| `FwdEuler.Data.CFL.Value` | `0.5` | 显式推进固定 CFL |

总迭代步数上限由**停止条件**控制（`MaxNumberSteps.nbSteps`，9.3.3）；`NewtonIterator.Data.MaxSteps` 另可限制外层 Newton 循环步数（与停止条件双保险）。收敛检查/屏幕输出频率为 `ConvRate`/`ShowRate`（9.3.2）。

显式推进（`FwdEuler`）与隐式推进（`NewtonIterator` + LSS）的选择逻辑见第 4.7 节决策树；FR/SD 高阶方法的 `BDF2/BDF3/CrankNicholson` 时间格式参数见第 4.7.6 节（隐式族）。

## 9.4 网格格式支持

### 9.4.1 原生 `.CFmesh` 格式（ASCII，实测 `plugins/Burgers/testcases/burgers.CFmesh`）

`!` 开头的**键值头** + 顺序数据段：

```
!COOLFLUID_VERSION 2013.9          # 生成器版本
!CFMESH_FORMAT_VERSION 1.3         # 格式版本
!NB_DIM 2                          # 维数
!NB_EQ 1                           # 方程数（守恒量个数）
!NB_NODES 1670 0                   # 节点数（第二个数为 ghost 节点数）
!NB_STATES 3178 0                  # 状态数（单元中心解点数）
!NB_ELEM 3178                      # 单元总数
!NB_ELEM_TYPES 1                   # 单元类型数
!GEOM_POLYORDER 1                  # 几何多项式阶
!SOL_POLYORDER 0                   # 解多项式阶（0 = FVM 单元均值）
!ELEM_TYPES Triag                  # 单元类型清单
!NB_ELEM_PER_TYPE 3178
!NB_NODES_PER_TYPE 3
!NB_STATES_PER_TYPE 1
!LIST_ELEM                         # 单元连接表：每行 节点ID… + 单元ID
38 39 40 0
...
!NB_TRSs 4                         # TRS（拓扑区域）数量
!TRS_NAME FaceSouth                # 各 TRS：名称/TR 数/几何实体数/类型/实体表
!NB_TRs 1
!NB_GEOM_ENTS 40
!GEOM_TYPE Face
!LIST_GEOM_ENT
...
!EXTRA_VARS
!LIST_NODE                         # 节点坐标表
!LIST_STATE 1                      # 状态表（解向量）
!END
```

要点：

- **TRS 段**是边界条件与面清单的锚点：CFcase 中 `listTRS` 的名字必须与文件内 `!TRS_NAME` 一致；
- **状态数 ≠ 节点数**：FVM 下 `NB_STATES` = 单元数（含 ghost 单元数=第二个数）；`SOL_POLYORDER` 大于 0 时为高阶（FR/SD/DG，`NB_STATES_PER_TYPE > 1`）；
- **二进制变体**：大网格用二进制读取，`CFmeshFileReader.Data.ReadCFmesh = ParReadCFmeshBinary`（命令注册名，实测 `ParReadCFmesh.cxx:33`；默认 MPI 版为 `ParReadCFmesh` 读 ASCII）。二进制文件由 `ParCFmeshBinaryFileReader` 以 MPI-IO 并行读取并配合 ParMetis 剖分；
- **只转换不装载**：`CFmeshFileReader.Data.onlyConversion = true` 时仅把外部格式转成 `.CFmesh` 而不载入内存（批量转换场景）；`convertBack = true` 反向写回原格式（调试用，均为 `CFmeshReader::defineConfigOptions` 实测键）；
- 写回（续算/输出）用 `OutputFormat = CFmesh`，由 `ParCFmeshFileWriter` 完成（`IO rank is 0` 为并行写汇总行，实测输出见 9.5.4）。

### 9.4.2 外部格式转换（`Xxx2CFmesh` 插件家族）

| 源格式 | 插件（转换器注册名） | convertFrom 值 | 说明 |

| Gambit | `plugins/Gambit2CFmesh/` | `Gambit2CFmesh` | `.neu`（Fluent Gambit） |

**用法一：求解器内直接转换**（推荐，`CFmeshReader` 实测）：


**用法二：独立转换**：转换器插件无独立可执行文件（`install/bin/` 仅有 `ConvertStructMesh`/`xcfcase_converter`），网格转换统一走用法一。

### 9.4.3 结构网格转换 `ConvertStructMesh`

独立命令，面向多块结构网格（Block/Quad/GridPro）：

```
./install/bin/ConvertStructMesh \
  --converter Block \                # 转换器注册名：Block / Quad / GridPro
  --meshFile  block.mesh \           # 源网格
  --meshType  FVM                    # FVM 或 FEM
```

参数（`plugins/ConvertStructMesh/main.cxx:34-36` 的 `AppOptions` 实测）：`--converter`（转换器注册名）、`--meshFile`、`--meshType`、`--bdir/--ldir/--log/--help`。输出 `.CFmesh`（FVM 模式写单元均值解结构）。

> ⚠️ **注册名与类名不同**：三个转换器的 C++ 类是 `ConvertBlockMesh`/`ConvertQuadMesh`/`ConvertGridProMesh`，但 Provider 注册名是 **`Block`**（`ConvertBlockMesh.cxx:37`）、**`Quad`**（`ConvertQuadMesh.cxx:34`）、**`GridPro`**（`ConvertGridProMesh.cxx:37`）。旧版手册示例写 `--converter ConvertBlockMesh` 会报 `NoSuchValueException: In factory of [ConvertStructMesh] a provider with the name [ConvertBlockMesh] was not found`——正是 12.3.1 所述的"注册名拼写不一致"错误。
>
> 注意**不要裸传位置参数**——转换器名必须经 `--converter` 给出（否则报 `provider with the name [] was not found`）。

### 9.4.4 网格质量要求与常见问题

| 问题 | 症状 | 处理 |
|------|------|------|
| 单位不一致（mm vs m） | 雷诺数/时间步异常 | `MeshScalingFactor` 或 `ScalingVector`（9.3.10） |
| 手写网格右手系反了 | 单元法向反、收敛崩 | 转换工具中检查单元顺序 |
| TRS 命名不一致 | 报"TRS not found" | `listTRS` 与 `!TRS_NAME` 逐名核对 |
| 负体积单元 | 初始化即 NaN | 用 `test_analyticaldm`（install/bin 附带工具）或 Tecplot 检查 |
| ghost 单元缺失（多块拼接） | 并行边界数据错 | 用 `CFmeshCellSplitter` 等预处理工具（第 4.13 节） |
| 高阶解不收敛 | `SOL_POLYORDER` 与方法不匹配 | 高阶算例用 `CFmeshCellSplitter` 升阶网格（P1→P2，第 4.13 节） |

## 9.5 运行方式

### 9.5.1 命令行完整参考（`apps/Solver/coolfluid-solver.cxx` 的 `AppOptions` 实测）

| 参数 | 类型 | 默认 | 含义 |
|------|------|------|------|
| `--scase <文件>` | string | 空（必填，缺失时打印帮助） | CFcase 文件路径；相对路径自动拼接 `--bdir` |
| `--conf <文件>` | string | `coolfluid-solver.xml` | 求解器环境 XML 配置（存在才读取） |
| `--bdir <目录>` | string | 空 | 基目录，前缀到所有文件/目录路径 |
| `--ldir <目录>…` | vector | 空 | 插件库搜索目录（可多个） |
| `--log <级别>` | CFuint | INFO（600） | 主日志级别（`CFLogLevel` 枚举值：INFO=600、VERBOSE=650、DEBUG_MIN=700，`src/Common/CFLog.hh` 实测） |
| `--help` | bool | false | 打印用法并退出（`-h/--h/--?/?` 均可） |
| `--testEnv` | bool | false | 只测试环境（解析+配置+setup），不跑模拟 |
| `--wait` / `--waitend` | bool | false | 开始/结束前暂停等待调试器（打印 PID） |
| `--residual <值>` | CFreal | 无穷大 | 目标残差：结束比对 `SimulationStatus` 最后残差，超差返回码 1 |
| `--tolerance <%>` | CFreal | 3.0 | `--residual` 模式允许的相对误差百分比 |

其他行为（实测）：

- **未处理参数**：`OptionList::setStrictArgs(true)`——任何未被消费的参数都会打印 `Unused argument:` 并以退出码 1 结束；
- **布尔选项必须空格传值**：`--testEnv 1`、`--help 1` 正确；`--help=1` 或裸 `--help` 会报 `BadMatchException`（`=1` 被当作未消费参数、裸 `--help` 缺值）——这是与常见 GNU 习惯最大的差异，第 0.3.1 节同此；
- **回归测试模式**：`--residual X --tolerance T` 下程序自动输出 `Target/Achieved/Percent diff` 并给出通过/失败返回码——这是 CI/算例测试的标准用法（配合第 7 章各档案头注释的 `### Residual` 值）；
- **日志文件**：`P<rank>-output.log`（主日志，`CFEnv.MainLoggerFileName` 可改，默认 `output.log`）；`P<rank>-TRACE-output.log`（追踪，`TraceActive` 时）；启动时 rank 0 自动清理当前目录旧 `config*.log` 与 `*-output.log`（实测 `main()` 224–246 行）。

### 9.5.2 串行与 MPI 并行

- **串行**：`./coolfluid-solver --scase x.CFcase`；
- **并行**：`mpirun -np N ./coolfluid-solver --scase x.CFcase`——**无需预剖分**！多进程下 `ParCFmeshFileReader` 自动调用 ParMetis 剖分器（`Partitioner = ParMetis` 默认；`Dumb` 关闭）把网格分到各 rank，随后各 rank 各写自己的输出块（`AppendRank` 或合并工具，第 10.1.1 节）；
- **负载均衡重剖分**：算到一半想重新分块用 `ParMetisBalancer` 插件（`StdRepart` 命令，第 6.1 节插件分类表）；
- **多子系统**：`SubSystemRanks = 0:3;4:7` 形式把不同子系统派到不同进程组（耦合计算，第 6.2.11 节）；
- **`OnlyMeshSubSystem`**：只建网格不求解的子系统的类型（`src/Framework/OnlyMeshSubSystem.hh`，供解耦/网格预处理用）。

### 9.5.3 环境变量与运行目录约定

- 相对路径（`--scase`、`WorkingDir`、`ResultsDir`、`FileName`）都相对 `--bdir` 解析（`DirPaths` 拼接，实测 `main()`）；
- `--ldir` 追加插件搜索路径；`Simulator.Paths.ModulesDir` 在 CFcase 内等价追加；
- `LD_LIBRARY_PATH` 需含 `install/lib`（或经 `--ldir`）；CUDA 构建下 `NTHREADS_PER_BLOCK` 等由设备属性自动确定（实测启动横幅，9.5.4）；
- 惯例：每个算例一个目录，`WorkingDir = .`，结果输出到 `ResultsDir`。

### 9.5.5 重启动（续算）

1. **保存检查点**：CFcase 中 `OutputFormat = CFmesh`（`CFmesh.SaveRate = N` 定期保存 `*.CFmesh`，内含当前解向量与迭代信息）；
2. **开启重启动**：把 `Simulator.SubSystem.CellCenterFVM.Restart = true` 加入 CFcase（`SpaceMethod::Restart`，`src/Framework/SpaceMethod.cxx:35` "Option to restart the SpaceMethod from the solution provided"）；
3. **机制**：Maestro 发出 `CF_ON_MAESTRO_MODIFYRESTART` 事件 → `SpaceMethod::modifyRestartAction` → `MeshCreator::modifyFileNameForRestart` 把网格文件名替换为保存的检查点（日志打印 `Restarting from file : <filename>`，实测 `StandardSubSystem.cxx:925`）；
4. **注意**：停止条件换成续算目标（如 `MaxNumberSteps.nbSteps = 续算步数`）；非定常续算需在 `ModifyRestart` 事件中恢复物理时间（`SimulationStatus` 的 `startTime` 机制，见 `tools/scripts/Python/CFcase_script.py` 的 restart 分支）。
