# 第 8 章 安装与编译指南

本章给出从零安装 COOLFluiD 的完整流程。**重要前置说明**：

- 本仓库版本基线：`COOLFluiD 2013.9` + Kernel `2.5.0`，代码基于 **C++98/03 风格**编写，CMake 最低要求 `2.8.3`（顶层 `CMakeLists.txt` 实测）；
- 在**现代工具链**（GCC ≥ 11、C++17、CUDA ≥ 12、Boost ≥ 1.79、PETSc ≥ 3.13）下编译，必须执行 8.3.5 节的**兼容性修复**——否则会碰到 C++17 移除 `throw()`、`std::filesystem` 命名冲突等错误（8.6 节速查表）；
- 两条构建路径：**(A) `prepare.pl` 辅助流程**（官方推荐，读取 `coolfluid.conf`，自动生成构建目录与 CMake 缓存）；**(B) 直接 CMake 流程**（全手动，适合脚本化 CI）。

## 8.1 依赖库清单

### 8.1.1 必需依赖

| 依赖 | 最低版本 | 用途 | 实测依据 |
|------|----------|------|----------|
| CMake | 2.8.3 | 构建系统 | 顶层 `CMAKE_MINIMUM_REQUIRED( VERSION 2.8.3 )` |
| C/C++ 编译器 | GCC ≥ 4.8（现代环境建议 ≥ 11） | 编译 | `PROJECT(COOLFluiD C CXX)` |
| Fortran 编译器 | gfortran 任意 | 部分依赖库/F77 源码 | `ENABLE_LANGUAGE(Fortran)`（可 `-DCF_SKIP_FORTRAN=ON` 跳过） |
| Boost | ≥ 1.42 | 智能指针/线程/文件系统/正则 | `FIND_PACKAGE(Boost)`，组件：`thread filesystem system regex unit_test_framework`；**1.79/1.85/1.88 需追加 `atomic`** |
| ZLIB | 任意 | 压缩 | `FIND_PACKAGE(ZLIB)` |
| BZip2 | 任意 | 压缩（**非单可执行模式**） | `FIND_PACKAGE(BZip2)` |
| MPI（可选但强烈建议） | 任意（MPICH/OpenMPI） | 并行 | `CF_ENABLE_MPI` 默认 **ON** |

> Boost 未找到时配置**直接中止**（`MESSAGE(FATAL_ERROR "Boost is required ...")`）；版本检测自动定义 `CF_HAVE_BOOST_1_60/1_62/1_66/1_70/1_72/1_76/1_79/1_82/1_85/1_88/1_59/1_55/1_54/1_53/1_47/1_42` 宏（顶层 CMakeLists 实测全表）。

### 8.1.2 网格分区库

| 依赖 | 用途 | 实测依据 |
|------|------|----------|
| **Metis** | 串行域分解 | `FIND_PACKAGE(Metis)`（`cmake/FindMetis.cmake`） |
| **ParMetis** | 并行域分解 | `FIND_PACKAGE(Parmetis)`（`cmake/FindParmetis.cmake`，含 metis 校验） |

> 未找到时对应插件（`ParMetisBalancer` 等）**自动跳过**，不影响核心编译。

### 8.1.3 可选外部库

| 库 | 开关 | 用途 | 找不到时 |
|----|------|------|----------|
| PETSc | （`CF_HAVE_PETSC` 检测） | 隐式线性求解（Petsc 插件） | 隐式算例不可用 |
| Pardiso | `CF_HAVE_PARDISO` | 商业稀疏求解 | Pardiso 插件跳过 |
| SAMG | `CF_HAVE_SAMG` | 代数多重网格 | SAMGLSS 插件跳过 |
| Mutation++ | `-DCF_ENABLE_MUTATIONPP` / `CF_ENABLE_MUTATIONPP_DEBUG` | 热化学非平衡物性 | NEQ/ICP 链不可用 |
| PLATO | `-DCF_ENABLE_PLATO` | 等离子体物性 | PlatoI 插件跳过 |
| PARADE | `CF_ENABLE_PARADE` | 辐射谱带 | 谱带算例不可用 |
| Trilinos | `prepare.pl` 库清单 | 求解器后端 | Trilinos 插件跳过 |
| CUDA | `-DCF_ENABLE_CUDA` | GPU 内核 | CUDA 插件跳过 |
| ViennaCL | `CF_ENABLE_CUDA+CF_ENABLE_VIENNACL` | GPU 线性代数 | — |
| GSL | `-DCF_ENABLE_GSL` | 数学库 | — |
| Curl | `-DCF_ENABLE_CURL` | 按需下载 | — |
| Valgrind / GooglePerftools | 自动探测 | 内存检查/性能剖析 | 静默跳过 |

`prepare.pl` 内置的依赖库清单（实测 `tools/scripts/install-coolfluid-deps.pl`，脚本 `%deps` 哈希实际定义 **33** 个）：`coreutils make wget binutils m4 tar gcc4 gcc3 autoconf automake libtool openssl blas clapack lapack log4cpp zlib cppunit dateshift curl libfaketime mpich mpich2 parmetis hdf5 subversion trilinos petsc gmsh ccache distcc cgnslib cgnstools`。⚠️ 旧版误写为"36 个"且清单含 `boost`/`openmpi`/`mvapich2`/`cmake`——**这些并非脚本依赖项**（`cmake` 的定义在脚本中已被注释掉；MPI 实现与 Boost 由系统包提供，不在本脚本内）。另注意脚本含 `libfaketime`（时间戳工具，旧清单遗漏）——可用该脚本自动下载编译安装（`--dependencies --install-dir <dir>`）。

### 8.1.4 依赖探测机制

- 探测脚本集中在 `cmake/`，**共 13 个** `FindXxx.cmake`（实测全表）：`FindBoost`、`FindMPI`、`FindCUDA`、`FindMetis`、`FindParmetis`、`FindBlasLapack`、`FindCBlas`、`FindGSL`、`FindCurl`、`FindMutationpp`、`FindPLATO`、`FindGooglePerftools`、`FindValgrind`；另有一批 `Check*.cmake`（编译器特性检测）与 `Find*` 配套的跳过开关（如 `CF_SKIP_CURL`、`CF_SKIP_GSL`、`CF_SKIP_MUTATIONPP`、`CF_SKIP_PLATO`）；
- 每个探测结果写为缓存变量 `CF_HAVE_*`，由各插件 `CMakeLists.txt` 决定**编译与否**（未满足依赖的插件自动跳过并打印提示）；
- 全部探测结果记录在 `CMakeLogInfo.txt`（构建目录）与配置末尾的"configuration summary"（含编译器/标志/MPI/CUDA/Boost 版本等，实测日志格式）。

## 8.2 编译选项与配置

### 8.2.1 全局选项全表（`-D<选项>=ON/OFF`）

| 选项 | 默认 | 说明 |
|------|------|------|
| `CMAKE_BUILD_TYPE` | `RelWithDebInfo` | `None/Debug/Release/RelWithDebInfo/MinSizeRel` |
| `CMAKE_INSTALL_PREFIX` | 系统默认 | 安装根目录 |
| `CF_ENABLE_MPI` | ON | MPI 并行（未找到 MPI 时自动降级 `CF_HAVE_MPI=0`，`DefineGlobalOptions.cmake` 实测） |
| `CF_ENABLE_CUDA` | OFF* | CUDA 支持（启用后 `ENABLE_LANGUAGE(CUDA)` 并追加 `.cu` 源扩展） |
| `CF_ENABLE_OMP` | OFF* | OpenMP（定义 `CF_HAVE_OMP`） |
| `CF_ENABLE_VIENNACL` | OFF* | ViennaCL（需与 CUDA 同开，顶层 `IF (CF_ENABLE_CUDA AND CF_ENABLE_VIENNACL)`） |
| `CF_ENABLE_CURL` | OFF* | curl 按需下载 |
| `CF_ENABLE_GSL` | OFF* | GSL 数学库 |
| `CF_ENABLE_STATIC` | OFF | 全静态链接（Linux `-Wl,-whole-archive`、Darwin `-all_load`，`DefineGlobalOptions.cmake` 实测） |
| `CF_ENABLE_SINGLEEXEC` | OFF* | 单可执行文件模式（不产生动态库；定义 `CF_HAVE_SINGLE_EXEC`） |
| `CF_ENABLE_LOG4CPP` | OFF* | 完整 log4cpp 日志（定义 `CF_HAVE_LOG4CPP`） |
| `CF_ENABLE_IBMSTATIC` / `CF_ENABLE_CRAYSTATIC` | OFF* | IBM/Cray 专用静态模式（定义 `CF_HAVE_IBMSTATIC/CRAYSTATIC`） |
| `CF_ENABLE_MUTATIONPP` / `CF_ENABLE_MUTATIONPP_DEBUG` | OFF* | 构建 Mutation++ 物性库接口（顶层 392 行与 `plugins/MutationppI` 实测） |
| `CF_ENABLE_PLATO` | OFF* | PLATO 等离子体物性 |
| `CF_ENABLE_ASSERTIONS` | ON | 断言（关闭时定义 `NDEBUG`） |
| `CF_ENABLE_TRACE` | ON | 追踪（关闭定义 `CF_NO_TRACE`） |
| `CF_ENABLE_LOGALL` / `CF_ENABLE_LOGDEBUG` / `CF_ENABLE_DEBUG_MACROS` | ON | 三级日志（关闭定义 `CF_NO_LOG` 等） |
| `CF_ENABLE_STDASSERT` | ON | 标准 `assert()` 函数 |
| `CF_ENABLE_GROWARRAY` | ON | `GrowArray` 增长数组容器 |
| `CF_ENABLE_WARNINGS` | ON | 大量编译警告 |
| `CF_ENABLE_TESTCASES` | ON | 从 CMake 系统检查算例（开启后联动 `CF_ENABLE_UNIT_TESTS/UNIT_CASES/PERFORMANCE_*`） |
| `CF_ENABLE_UNITTESTS` | OFF | 单元测试 |
| `CF_ENABLE_PARALLEL_VERBOSE` / `CF_ENABLE_PARALLEL_DEBUG` | OFF | 并行接口冗余输出/调试代码 |
| `CF_CMAKE_LIST_PLUGINS` | OFF | 配置期列出全部插件 |
| `CF_ENABLE_PROFILING` | OFF | 性能剖析（`CF_PROFILER_TOOL = gprof/google-perftools`） |
| `CF_ENABLE_DOCS` | ON | 文档构建 |
| `CF_ENABLE_EXPLICIT_TEMPLATES` | ON | 显式模板实例化 |
| `CF_ENABLE_INTERNAL_DEPS` | ON | 库间内部依赖 |
| `CF_ENABLE_AUTOMATIC_UPDATE_MODULES` | OFF | 插件自动 SVN 更新 |
| `CF_SKIP_FORTRAN` | OFF | 跳过 Fortran 语言检测 |
| `CF_EXTRA_SEARCH_DIRS` | 空 | 外部插件搜索目录列表（含 `*.cmake` 配置与 `CMakeLists.txt` 模块，自动加入构建） |

> 表中标 `*` 的选项**未在 `cmake/` 中定义 CMake `OPTION`**（源码仅在 `IF(CF_ENABLE_…)` 处引用），未传 `-D` 时 CMake 按未定义处理、等效 OFF；启用统一用 `-DCF_ENABLE_XXX=ON`。其余行均可在 `cmake/DefineGlobalOptions.cmake` 找到默认值定义。

### 8.2.2 精度与整数宽度

| 选项 | 默认 | 说明 |
|------|------|------|
| `CF_PRECISION_SINGLE` | OFF | `CFreal` = float |
| `CF_PRECISION_DOUBLE` | ON | `CFreal` = double |
| `CF_PRECISION_LONG_DOUBLE` | OFF | `CFreal` = long double |
| `CF_ENABLE_LONG` | OFF | `CFuint` = unsigned long（`CF_HAVE_LONG`） |
| `CF_ENABLE_LLONG` | OFF | `CFuint` = unsigned long long（`CF_HAVE_LLONG`） |
| `CF_CUDA_MALLOC` | OFF | CUDA 显存用 `malloc`（`CF_HAVE_CUDA_MALLOC`） |

> 精度/整数宽度在编译期写死进 `coolfluid_config.h`，运行期不可切换；与 PETSc 等外部库的精度一致性需在安装依赖时对齐（`FindBlasLapack` 注释可见 `IDXTYPEWIDTH/REALTYPEWIDTH=64` 的开关）。

### 8.2.3 构建产物布局

- 动态库输出到构建目录 `dso/`（`COOLFluiD_DSO_DIR`，配置期自动创建）；插件库名 `lib<插件名>.so`；
- 安装布局（`CF_INSTALL_BIN_DIR=bin`、`CF_INSTALL_LIB_DIR=lib`、`CF_INSTALL_INCLUDE_DIR=include/coolfluid`、`CF_INSTALL_DATA_DIR=data`）；
- RPATH：构建期全 RPATH，安装 RPATH 指向 `${CMAKE_INSTALL_PREFIX}/lib`；
- 库版本：`VERSION 2013.9` + `SOVERSION 2013.9`（`CF_NO_LIBRARY_VERSION` 可关）。

### 8.2.4 个人覆盖与外部插件

- **个人选项文件**：构建目录下 `coolfluid.cmake` 会被自动 `INCLUDE`（`INCLUDE(${COOLFluiD_BINARY_DIR}/coolfluid.cmake OPTIONAL)`，顶层实测）——多用户共享源码树时隔离个人 `-D`；
- **外部插件**：`CF_EXTRA_SEARCH_DIRS="dir1;dir2"`，每个含 `CMakeLists.txt` 的目录作为独立模块加入构建（`ADD_SUBDIRECTORY(… extra)`），其 `*.cmake` 配置也被解析；
- **Mutation 系列**：配置期检查源码目录 `plugins/Mutation`、`plugins/Mutation2.0`、`plugins/Mutation2.0.0` 是否存在，自动设置 `CF_HAVE_MUTATION1/CF_HAVE_MUTATION2/CF_HAVE_MUTATION2OLD`（实测）。

### 8.2.5 `prepare.pl` 桥接层与 `coolfluid.conf`

`prepare.pl` 读取**小写文件名** `coolfluid.conf`（根目录；仓库自带 `COOLFluid.conf` 旧名与 `tools/conf/` 下多平台示例），支持 `--build=optim` 等选项（实测默认选项含）：

| conf 键 | 含义 |
|---------|------|
| `coolfluid_dir/basebuild_dir/install_dir` | 源码/构建/安装根 |
| `cc/cxx/fc`、`cudac` | 编译器路径 |
| `withcuda/withcuda_malloc`、`cuda_dir/cudacflags` | CUDA 开关与 nvcc 标志 |
| `withmpi/mpi_dir/mpi_extra_libs` | MPI 与路径 |
| `with_mutationpp/with_plato/with_paralution/paralution_dir` | 物性/求解器库 |
| `with_singleexec`、`allstatic/with_ibmstatic/with_craystatic` | 链接模式 |
| `nofortran/withcurl/withdocs/with_testcases/with_log4cpp` | 功能开关 |
| `cflags/cxxflags/fflags/cudacflags/ldflags`、`optim_cxxflags` 等 | 编译/链接标志（含 `-std=c++17` 需求） |
| `allactive/search_dirs/extra_search_dirs/extra_mods_url` | 模块收集 |
| `cmake_generator` | `make` 或 VS 生成器名 |

除 `--config-file` 指向 conf 外，`prepare.pl` 还支持大量命令行开关（实测 `--help` 全表）：`--build=<名字>`（隐含 `--config`，生成 `<basebuild_dir>/<名字>/`）、`--config`（仅配置）、`--allactive`/`--allstatic`/`--with_singleexec`/`--with_unit_tests`、`--basebuild_dir`/`--coolfluid_dir`/`--install-dir`、`--cmake_generator`、`--extra-search-dirs`、`--libpetsc_name`/`--libparmetis_name`/`--libmetis_name`（默认 `petsc/parmetis/metis`）、`--find`（仅报告模块）、`--mods-*`（SVN 模块管理）、`--dry-run`/`--nodeps`/`--verbose`/`--nocolor`。

生成目录：`<basebuild_dir>/optim`（`--build=optim`）或 `RelWithDebInfo` 默认值。

## 8.3 Linux 完整安装流程（Ubuntu 22.04 实测基线）

### 8.3.1 安装系统依赖

```bash
sudo apt update
sudo apt install -y build-essential gfortran cmake libboost-all-dev \
  libopenmpi-dev openmpi-bin zlib1g-dev libbz2-dev libcurl4-openssl-dev
# 可选：PETSc（建议源码装，需 MPI 一致的构建）、ParMetis、Mutation++
```

### 8.3.2 获取源码

```bash
git clone https://github.com/andrealani/COOLFluiD.git && cd COOLFluiD
```

### 8.3.3 安装可选依赖（PETSc / ParMetis / Mutation++）

- **PETSc**（Petsc 插件必需）：`./configure --with-cc=mpicc --with-cxx=mpicxx --with-fc=mpif90 --with-debugging=0`，记下安装路径供 `petsc_dir`；
- **ParMetis**：标准 `make config`（需先装 metis）；**Mutation++**：`cmake -DCMAKE_INSTALL_PREFIX=…` 标准流程，需先装 **Eigen3**（8.6.2 节有 include 路径坑）；
- 或一键：`perl tools/scripts/install-coolfluid-deps.pl --dependencies --install-dir $HOME/local/coolfluid_deps`（自动下载编译依赖库，脚本共定义 36 个库，实测清单见 8.1.3）。

### 8.3.4 配置与生成

创建 `coolfluid.conf`（小写！模板见 8.2.5 键表；仓库示例：`tools/conf/coolfluid.conf.minimal`、`coolfluid.conf.vki.example`），然后：

```bash
./prepare.pl --build=optim
```

脚本生成 `<源码>/build/optim/` 与 CMake 缓存。**注意**：每次重跑 `prepare.pl` 会重置缓存，需重放 8.3.6 的手动 cmake 补全。

### 8.3.5 现代工具链兼容性修复（C++17 迁移，实测清单）

| # | 问题 | 修复对象（实测文件） | 对应脚本 |
|---|------|----------------------|----------|
| 1 | C++17 移除 `throw()` 动态异常规范 | `src/logcpp/Category.cpp`、`src/logcpp/Priority.cpp`、`src/Common/Exception.hh/.cxx`、`src/Common/FilesystemException.cxx`、`NoSuchValueException.cxx`、`ParserException.cxx`、`src/Framework/InterpolatorRegister.hh/.cxx`、`plugins/THOR2CFmesh/CheckNodeNumberingHexa.hh/.cxx`——删除 `throw(...)` 或改 `noexcept` | `tools/fix_exception_specs.sh` |
| 2 | `std::filesystem` 与 `boost::filesystem` 命名冲突 | `apps/Solver/coolfluid-solver.cxx`：`namespace fs = boost::filesystem;` 并替换 `filesystem::` → `fs::` | `tools/fix_compile_issues.sh` [1/4] |
| 3 | PETSc ≥ 3.13 移除 `PCSACUSP` 等 CUDA 预条件器常量 | `plugins/Petsc/PetscOptions.cxx`：条件改为 `#if PETSC_VERSION_MINOR>=13 … #else` | `tools/fix_compile_issues.sh` [2/4] |
| 4 | Mutation++ 头文件引用 `Eigen/Dense` 但未加 include 路径 | `plugins/MutationppI/CMakeLists.txt`：追加 `LIST(APPEND MutationppI_includedirs ${EIGEN3_INCLUDE_DIR})` | `tools/fix_compile_issues.sh` [3/4] |
| 5 | nvcc + C++17 对从属模板名要求 `template` 关键字 | `plugins/FiniteVolumeCUDA/FVMCC_ComputeRHSCell.cu`：`d_castTo<…>()` → `.template d_castTo<…>()` | `tools/fix_compile_issues.sh` [4/4] |

仓库提供一键脚本：`bash tools/apply_all_fixes.sh`（实测执行两步：`fix_exception_specs.sh` + `fix_compile_issues.sh`，均为幂等 sed 修改，脚本内自带"已修复则跳过"判断）。

### 8.3.6 补全 CMake 缓存并编译

```bash
cd build/optim
cmake -DCF_CUDAC_FLAGS="--std c++17 -arch sm_86" \
      -DCMAKE_CUDA_FLAGS="--std c++17 -arch sm_86" \
      -DEIGEN3_INCLUDE_DIR=/usr/include/eigen3 \
      -DPETSC_INC_DIR="$PETSC_DIR/include;$PETSC_DIR/arch-linux-c-opt/include" \
      .
make -j$(nproc) 2>&1 | tee build.log
```

耗时参考（RTX 3050 + 14 核实测）：首次全量约 40–60 分钟；增量约 5–15 分钟。监控：`grep -oP '\[\d+%\]' build.log | tail -3`。

### 8.3.7 安装

```bash
make install
```

产物（本机实测，2025-06 构建）：`install/bin/`：`coolfluid-solver`（2.6 MB）、`ConvertStructMesh`（6.8 MB）、`coef_merge`、`tecplot_merge`、`tecplot_merge_kopacek`、`test_analyticaldm`、`xcfcase_converter`；`install/lib/`：**167 个** `lib*.so`（含全部内核库与已启用插件）。

### 8.3.8 验证

```bash
install/bin/coolfluid-solver --help 1          # 注意：布尔选项须用空格分隔传值（--help=1 不被识别）
ldd install/bin/coolfluid-solver | grep -iE 'cuda|mpi'   # 链接检查
# 运行最小算例（先核对 Modules.Libs，见下方注意事项）
cd plugins/Burgers/testcases
../../../install/bin/coolfluid-solver --scase burgersFVM.CFcase
```

> **重要——`Modules.Libs` 与 `libShapeFunctions`**：`burgersFVM.CFcase` 的 `Simulator.Modules.Libs` 未列出 `libShapeFunctions`，而几何实体（GE）provider（如 `CellTriagLagrangeP1LagrangeP1`，`src/ShapeFunctions/LagrangeCellTriags.cxx` 注册）全部在此库中、**只随 `dlopen` 注册**；本机实测直接运行会崩在 `GeometricEntityRegister::regist` 的 `FACTORY_EXISTS_PROVIDER(GeometricEntity,...)` 断言。解决二选一：
> 1. 在 CFcase 的 `Modules.Libs` 末尾追加 `libShapeFunctions`（实测 85 个官方 CFcase 显式列出它；追加后 burgersFVM 完整跑通：325 步、残差 **-5.00049**，与文件头注释 `### Residual = -5.00048764` 吻合）；
> 2. 或改跑本身含依赖库的算例（如 `accpulse2d-sfvm.CFcase`——`libSpectralFV` 链入 `libShapeFunctions`，无需显式列出）。

### 8.3.9 直接 CMake 流程（免 prepare.pl）

```bash
mkdir build && cd build
cmake -DCMAKE_BUILD_TYPE=RelWithDebInfo -DCMAKE_INSTALL_PREFIX=$PWD/../install \
      -DCF_ENABLE_MPI=ON -DCF_ENABLE_CUDA=OFF .. 
make -j$(nproc) && make install
```

> 顶层 CMakeLists 要求 **out-of-source** 构建（源码目录内运行 cmake 直接 `FATAL_ERROR`，实测）。

## 8.4 macOS 安装

- **依赖**：`brew install cmake gcc open-mpi boost zlib bzip2`（PETSc 建议 `brew install petsc` 或源码装）；
- **静态链接规则**（实测顶层 CMakeLists）：Darwin 下 `CF_ENABLE_STATIC` 用 `-all_load`（区别于 Linux 的 `-Wl,-whole-archive`）；
- **要点**：Clang 工具链下推荐 `tools/conf/` 的 clang 配置示例（`coolfluid.conf.MF.static.clang` 等）；C++17 修复同 8.3.5；`-arch` 标志按 Apple Silicon（arm64）/Intel 区分；
- 其余步骤与 Linux 相同。

## 8.5 Windows 安装

- **官方支持路径**：CMake 生成 Visual Studio 工程——顶层 CMakeLists 实测注释：`-G"Visual Studio 9 2008"`（历史基线 VS2008；新版 VS 需更高 CMake 版本，`CMAKE_ALLOW_LOOSE_LOOP_CONSTRUCTS` 等兼容策略已内建）；
- **辅助脚本**（实测 `tools/win32/`）：`prepare.bat`（配置）、`runcf.bat`（运行算例）、`update.bat`（更新源码）；
- **编译器**：需 MSVC + Intel Fortran（或 `-DCF_SKIP_FORTRAN=ON`）；Boost 需预编译二进制；CUDA Windows 版 nvcc 支持同 8.6.3；
- 备选：MSYS2/Cygwin 提供类 Unix 环境，但官方未维护，插件全量编译以 VS 生成器为基准；
- Windows 下 C++17 修复（8.3.5）同样适用（MSVC 已移除 `throw()`）。

## 8.6 常见编译错误与解决方案

### 8.6.1 C++17 迁移族

| 错误现象 | 根因 | 解决 |
|----------|------|------|
| `dynamic exception specification` / `throw()` 相关 | C++17 移除该语法 | 8.3.5 之 1（或全局 `sed -i 's/throw()//'` 指定文件） |
| `destructor throw() always calls terminate` | C++11 起析构默认 noexcept | 非致命，可忽略 |
| `auto_ptr is deprecated` | C++17 移除 `std::auto_ptr` | 需重构为 `unique_ptr`（量大，建议保持 `-std=gnu++14` 编译作为备选） |
| `filesystem is ambiguous` | std 与 boost 命名冲突 | 8.3.5 之 2 |

### 8.6.2 依赖库族

| 错误现象 | 根因 | 解决 |
|----------|------|------|
| `Boost is required to compile COOLFluiD Kernel` | Boost 未找到 | 装 boost-dev；或 `-DBOOST_ROOT=…`；版本 ≥ 1.42 |
| Boost `atomic` 头文件错误 / `redefinition of constexpr` | Boost 1.79+ 需 atomic 组件且需 C++17 | 顶层 CMake 已自动追加 atomic；确保 `-std=c++17` 生效 |
| `petscvec.h not found` | CMake 缺 PETSc include 路径 | 8.3.6 的 `-DPETSC_INC_DIR` 补全 |
| `Eigen/Dense not found` | Mutation++ 依赖 Eigen3 路径缺失 | 8.3.5 之 4 + `-DEIGEN3_INCLUDE_DIR` |
| Metis/ParMetis 插件未生成 | `FindMetis/FindParmetis` 失败 | 先装 metis/parmetis，`-DCMAKE_PREFIX_PATH` 指向安装前缀 |

### 8.6.3 CUDA 族

| 错误现象 | 根因 | 解决 |
|----------|------|------|
| `atomicAdd no matching overload` | 未指定架构，默认 < sm_60 | `cudacflags` 加 `-arch sm_86`（按 GPU 表：30 系/A 系 sm_86、20 系/T4 sm_75、10 系 sm_60/61、A100 sm_80、H100 sm_90） |
| `type name is not allowed` in `.cu` | nvcc C++17 从属模板名 | 8.3.5 之 5（`.template d_castTo`） |
| `PCSACUSP was not declared` | PETSc ≥ 3.13 移除 CUDA PC 常量 | 8.3.5 之 3 |
| CUDA 编译标志未生效 | `prepare.pl` 重置缓存 | 每次重跑后重放 8.3.6 cmake 命令 |

### 8.6.4 其他

| 错误现象 | 根因 | 解决 |
|----------|------|------|
| `extended character is not valid in an identifier` | 源文件混入 U+00A0 不可见字符 | 用普通空格替换 |
| `malloc_info/mallinfo deprecated` | 系统 API 变更 | 非致命警告，忽略 |
| 配置期 `OrphanFiles.txt` 警告 | 源码目录含未纳入构建的文件 | 检查清单，通常无害 |
| `dso` 目录缺失 / 库找不到 | 未 out-of-source 构建或 RPATH 缺失 | 重建 build 目录；`--ldir <构建>/dso` 指定库路径 |
| `GeometricEntityRegister::regist` 断言失败（读网格即崩） | `Modules.Libs` 缺 `libShapeFunctions`（GE provider 只随 dlopen 注册） | 8.3.8 注意事项：追加 `libShapeFunctions` 或改用依赖它的算例 |
| `argument expected for help` / `no option '--help=1'` | 命令行布尔选项需空格传值 | 写 `--help 1`、`--testEnv 1`（等号形式不被识别） |
| 内存不足编译崩溃 | `make -j` 过大 + 模板重编译 | 降 `-j`；对 `FluxReconstructionMethod` 等重模板目录串行编译 |

**排查总则**：`tail -100 build.log` → 构建目录 `CMakeLogInfo.txt`（探测详情）→ 配置末尾 summary（开关生效确认）→ 运行期 `coolfluid-solver --testEnv`。
