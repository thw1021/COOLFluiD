# 第 6 章 插件系统详解

本章回答"这个插件是什么、怎么开、喂什么参数、吐出什么、依赖谁、有什么坑"。约定：

- **统一模板**（重点插件）：【功能描述】【所属类别】【启用方式】【输入参数表】【输出结果】【依赖插件/外部库】【源代码文件清单】【验证算例】【已知限制】九段式；
- **所有取值均为实测**：`Modules.Libs` 行、`PhysicalModelType`、`SpaceMethod` 等键取自真实 CFcase；插件体量（源码数）与算例数由脚本对 `plugins/` 实测；
- 全量 135 插件的"一句话功能 + 源码计数"见第 5.8.16 节索引表，本章不再重复枚举，聚焦**如何使用**。

## 6.1 插件分类总表

## 6.2 重点插件详解

### 6.2.1 `NavierStokes` + `FiniteVolumeNavierStokes`——NS/Euler 物理与求解

**【功能描述】** 理想气体可压缩（及不可压）Euler/NS 的物理模型、变量集与 FVM 求解件（通量/BC/源项/热流统计）。

**【所属类别】** 流体物理模型 + 方法物理扩展。

**【启用方式】**（实测，Cylinder 系算例）

```
Simulator.Modules.Libs = libCFmeshFileReader libCFmeshFileWriter libTecplotWriter
  libNavierStokes libFiniteVolume libFiniteVolumeNavierStokes
  libRungeKutta2 libForwardEuler libNewtonMethod libPetscI
```

**【输入参数表】**（前缀 `Simulator.SubSystem.<模型名>.`）

| 键 | 取值示例 | 含义 |
|----|----------|------|
| `PhysicalModelType` | `NavierStokes2D`（Euler/NS × 1D/2D/3D，`IncompEuler2D`、`IncompNavierStokes2D/3D`） | 物理模型 |
| `refValues` | `(p,T,vx,vy)` | 有量纲参考值（→ 无量纲化 + 量纲恢复） |
| `refLength` | `1.0` | 参考长度 |
| `ConvTerm.machInf` / `ConvTerm.tempRef` | `0.84` / `273.15` | 来流马赫数/参考温度（`Puvt` 变量集无量纲化） |
| `DiffTerm.Reynolds` | `2500.` | 雷诺数（粘性项） |
| `isAxisymm` | `true/false` | 轴对称开关 |
| `SpaceMethod` | `CellCenterFVM` | FVM 方法 |
| `Data.FluxSplitter` | 第 4.4.7 节全表 | 对流通量 |
| BC 命令族 | 第 3.6 节 | `SuperInlet/SuperOutlet/Dirichlet/NoSlipWall*/…` |

**【输出结果】** 默认更新变量 `Puvt`（压力/三速度/温度）；经 `TecplotWriter/ParaViewWriter` 写出；`NavierStokesSkinFrictionHeatFluxCC2D/3D` 命令输出壁面摩擦与热流。

**【依赖】** `FiniteVolume`；`FiniteVolumeNavierStokes` 依赖 `NavierStokes`；时间推进/输出按需。

**【验证算例】** `NavierStokes/testcases/` 共 **420** 个 CFcase（AccPulse、Cylinder M15 圆柱、DoubleEllipse、Kheops LTE、前台阶等）。

**【已知限制】** 默认 γ 常数理想气体；高温离解/振动非平衡请切换 NEQ/LTE 链（6.2.2）。

---

### 6.2.2 `NEQ` + `FiniteVolumeNEQ`——热化学非平衡物理与求解

**【功能描述】** 高温空气热化学非平衡（化学非平衡 + 振动/电子能量非平衡）模型、变量集与 FVM 求解件。

**【启用方式】**（实测，`deNEQ_CRD.CFcase` / FireII）

```
Simulator.Modules.Libs = libCFmeshFileReader libCFmeshFileWriter libTecplotWriter
  libNEQ libFiniteVolume libFiniteVolumeNEQ
  libMutation2OLD libMutation2OLDI libAeroCoefFVM libAeroCoefFVMNEQ ...
```

**【输入参数表】**

| 键 | 取值示例 | 含义 |
|----|----------|------|
| `PhysicalModelType` | `NavierStokes2DNEQ`（CNEQ）等 | 非平衡模型（第 3.2.5 节全表） |
| `nbVibEnergyEqs` | `1` | 振动能量方程数（0=CNEQ，≥1=TCNEQ） |
| `includeElectronicEnergy` | `false/true` | 是否含电子能量方程 |
| `nbEqs` | `7` | 方程数（与组分/振动方程数联动） |
| `Data.UpdateVar/LinearVar` | `RhoivtTv / RoeVinokur` | 非平衡变量集（60 余注册名，第 5.8.3 节） |
| `NavierStokes2DNEQSourceTerm` | 源项命令 | 化学/振动源项（`ChemNEQST` 等） |
| 催化 BC | `NoSlipWallIsothermalNSrvtCat*` | 有限/完全催化壁族 |

**【输出结果】** 组分质量分数、振动温度随解输出；`AeroCoefFVMNEQ` 输出含催化贡献的壁面热流。

**【依赖】** `NEQ`、`FiniteVolumeNEQ`、物性库接口（`Mutation2OLD/MutationppI`）；**无物性库则无法运行**。

**【验证算例】** `NEQ/testcases/` 27 个；高焓标准算例群（FireII、DoubleEllipse 的 `deNEQ_CRD` 等）分布在 `NavierStokes/testcases/`。

**【已知限制】** 热力学/化学数据在物性库侧（`Mutation2.0I/data/` 26 种 `.mix`）；组分集合由库的混合气文件决定；变网格 RDS 算例需 `FluctSplitNEQ`。

### 6.2.3 `MHD` + `FiniteVolumeMHD`——磁流体物理与求解

**【功能描述】** 单流体理想/耗散 MHD 模型（守恒/投影变量），含 ∇·B 控制。

**【启用方式】**（实测 `MHD/testcases/`）

```
Simulator.Modules.Libs = libCFmeshFileReader libCFmeshFileWriter libTecplotWriter
  libMHD libFiniteVolume libFiniteVolumeMHD libBackwardEuler
```

**【输入参数表】**

| 键 | 取值示例 | 含义 |
|----|----------|------|
| `PhysicalModelType` | `MHD3DProjection` / `MHD2DProjection` / `MHD2D` / `MHD3D` | 模型（投影变量含 ∇·B 源） |
| `SpaceMethod` | `CellCenterFVM` | 方法 |
| `Data.FluxSplitter` | `AUSMPWMHD2D/3D`、Roe 型 | MHD 通量（第 3.2.4、4.4.7 节） |
| `Data.UpdateVar/LinearVar` | `MHD2DProjectionCons/Prim` 等 | 变量集 |
| 磁场初值/入口 | `InitState`（含 B 分量） | 磁场与流动同解 |

**【输出结果】** 速度+磁场分量随解输出；Tecplot/ParaView。

**【依赖】** `FiniteVolume`；物性无外部库。

**【验证算例】** `MHD/testcases/` **112** 个（ShockTube Powell/投影、COCONUT 系列、SolarWind、CoronalExpansion 等，7.4 节）。

**【已知限制】** 单温度模型；强磁激波需选择熵修正/投影策略控制 ∇·B 污染；多组分等离子体见 6.2.4。

---

### 6.2.4 `MultiFluidMHD` + `FiniteVolumeMultiFluidMHD`——多流体 MHD

**【功能描述】** 多组分（离子/电子/中性）多温度 MHD，各组分独立速度场。

**【启用方式】**（实测 `11_BrioWuTube/1_BrioWu.CFcase`）

```
Simulator.Modules.Libs = libCFmeshFileReader libCFmeshFileWriter libTecplotWriter
  libMultiFluidMHD libFiniteVolume libFiniteVolumeMultiFluidMHD libRKRD
```

**【输入参数表】**

| 键 | 取值示例 | 含义 |
|----|----------|------|
| `PhysicalModelType` | `MultiFluidMHD2D` / `MultiFluidMHD3D` | 模型 |
| `Data.UpdateVar` | `RhoiViTi`（各组分 ρ_i, **v**_i, T_i）/ `HalfCons` | 变量集 |
| `Data.FluxSplitter` | `AUSMPlusUpMultiFluid2D/3D`（+`ALE`）、`LaxFriedFluxMultiFluid2D/3D` | 多流体通量（⚠️ 注册名**无 `Flux`、无 `MHD` 中缀**，`AUSMPlusUpFluxMultiFluidMHD2D/3D` 不存在，见 4.4.7 表） |
| `nbSpecies`（模型层） | 2–3 | 组分个数 |
| 界面条件/源项 | 各组分壁面/入口命令 | 见第 3.2.4 节 |

**【输出结果】** 各组分的密度/速度/温度场分块输出。

**【依赖】** `FiniteVolume`；无外部物性库（理想气体多温度）。

**【验证算例】** `MultiFluidMHD/testcases/` **81** 个（BrioWu、磁鞘、航天器再入等离子体壳等）。

**【已知限制】** 方程数 = 组分×(NS+1)+磁场，计算量大；电离度/碰撞源项以简化模型为主。

### 6.2.5 `RadiativeTransfer`——辐射传输

**【功能描述】** DOM/Monte Carlo 辐射求解 + 谱带物性（HSNB/PARADE/Grey），与 NEQ 流场循环耦合。

**【启用方式】**（实测，经 `DataProcessing` 挂载）

```
Simulator.Modules.Libs = ... libNEQ libFiniteVolume libFiniteVolumeNEQ
  libRadiativeTransfer libAeroCoefFVM ...
Simulator.SubSystem.DataProcessing1.Comds = RadiativeTransferMonteCarlo2DFVMCC
Simulator.SubSystem.DataProcessing1.RT.RadiationPhysicsHandler.NumberLoops = 4
Simulator.SubSystem.DataProcessing1.RT.RadiationPhysicsHandler.TempID = 0
Simulator.SubSystem.DataProcessing1.RT.RadiationPhysicsHandler.WavelengthMin = 0.01
Simulator.SubSystem.DataProcessing1.RT.RadiationPhysicsHandler.WavelengthMax = 10.0
Simulator.SubSystem.DataProcessing1.RT.RadiationPhysicsHandler.RadiationPhysicsNames = aa b1 b2 b3
Simulator.SubSystem.DataProcessing1.RT.RadiationPhysicsHandler.aa.ApplyTRS = ...
```

**【输入参数表】**

| 键 | 说明 |
|----|------|
| `RadiationPhysicsHandler.*` | 主控：`NumberLoops`（辐射与流场交换频次）、`TempID`、波长范围、`RadiationPhysicsNames`（每个辐射体一个名字） |
| `<名>.ApplyTRS` | 该辐射体作用的面 TRS（如辐射热流壁） |
| 求解器（CFcase 内选） | `Solvers/`：`FiniteVolumeDOM`（离散坐标）、`FiniteVolumeSolar`、`MonteCarlo` |
| 谱带模型 | `Models/`：`HSNB`（含核心库）、`PARADE`、`Grey`、`ArcJet` |

**【输出结果】** 辐射源项回写流场能量方程（`omegRad`）、辐射热流输出（`RadiativeTransferOutputFVMCC` 命令）。

**【依赖】** 流场 NEQ 链；HSNB 谱数据（`data.tgz` 需解压）；PARADE 外部库（`CF_ENABLE_PARADE`）。

**【验证算例】** `RadiativeTransfer/testcases/` **50** 个（平板、柱、FireII 谱段对比）。

**【已知限制】** 温度场默认平衡假设；谱带库数据规模大；辐射-流场耦合为显式交换（`NumberLoops` 控制）。

### 6.2.6 `ICP` + `FiniteVolumeICP`、`ArcJet` + `FiniteVolumeArcJet`——感应等离子体与弧风洞

**【功能描述】** ICP 射频感应等离子体（LTE/NEQ 两种热力学路径）与电弧加热器风洞流动求解。

**【启用方式】**（实测 ICP 算例）

```
Simulator.Modules.Libs = libCFmeshFileReader libCFmeshFileWriter libTecplotWriter
  libICP libLTE libICPLTE libMutation libMutationI
  libFiniteVolume libFiniteVolumeNavierStokes libFiniteVolumeICP libNewtonMethod ...
```

**【输入参数表】**

| 键 | 说明 |
|----|------|
| `PhysicalModelType` | `ICPLTE2D` / `ICPNEQ2D/3D`（ICP）；`ArcJet*` 变体族（ArcJet） |
| 线圈/频率参数 | 感应线圈几何与射频频率（`ICP` 模型层选项） |
| `Simulator.SubSystem.InteractiveParamReader.FileName` | `.inter` 交互文件：功率/压力/流量运行工况逐点给定（45/15 个算例全程使用） |
| 谱带辐射 | 可选接 `RadiativeTransfer` 的 `ArcJet` 谱带 |

**【输出结果】** 温度/组分/流场 + 壁面热流；ICP 实验对照点数据。

**【依赖】** ICP 依赖 `LTE`/`Mutation*`（热力学）；ArcJet 依赖 `RadiativeTransfer` 谱带（可选）。

**【验证算例】** `ICP/testcases/` 45 个、`ArcJet/testcases/` 15 个。

**【已知限制】** 以 2D 轴对称为主；非平衡路径对物性库敏感。

### 6.2.7 `FluctSplit`——残差分布法（RDS）

**【功能描述】** 格点单元残差分布方法内核（LDA/N/LDA-PSI/FCT 分布矩阵）。

**【启用方式】**（实测 `doubleEllipseRDS_NS_Pvt_adim.CFcase`、`deNEQ_CRD.CFcase`）

```
Simulator.SubSystem.SpaceMethod = FluctuationSplit        # 注册名！
Simulator.Modules.Libs = libFluctSplit libFluctSplitScalar libFluctSplitSystem
  libFluctSplitNavierStokes libFluctSplitNEQ libFluctSplitSpaceTime
```

**【输入参数表】**

| 键 | 说明 |
|----|------|
| `SpaceMethod = FluctuationSplit` | 方法（注意：非 "FluctSplit"） |
| 分布格式 | 命令/选项选择 LDA/N/PSI/FCT 族 |
| BC | `Strong*` 强加族（含 `Impl` 隐式变体，第 3.6.4 节） |
| 时间推进 | `RKRD`（显式）或 `FS_SpaceTime`（时空格式，配 `libFluctSplitSpaceTime`） |

**【输出结果】** 节点值解；`CFmeshFileWriterFluctSplitP1P2` 支持 P1/P2 数据写出。

**【依赖】** 物理侧：`NavierStokes`/`NEQ`（+`FluctSplitNEQ`）等；无外部库。

**【验证算例】** 含在 `NavierStokes/testcases/DoubleEllipse/`（`doubleEllipseRDS*`、`deNEQ_CRD`）、`SubSystemCoupler/testcases/FSI/`（SpaceTime 变体）等。

**【已知限制】** 以三角形/四面体格点单元为主；隐式支持弱于 FVMCC。

### 6.2.8 `FluxReconstructionMethod` 及物理扩展——FR/CPR

**【功能描述】** 高阶通量重构方法内核 + 物理扩展插件族。

**【启用方式】**（实测 `cylinderEuler2DFR-impl.CFcase`）

```
Simulator.SubSystem.SpaceMethod = FluxReconstruction
Simulator.Modules.Libs = libCFmeshFileReader libCFmeshFileWriter libTecplotWriter
  libFluxReconstructionMethod libFluxReconstructionNavierStokes
  libBackwardEuler libPetsc libPetscI
```

**【输入参数表】**（前缀 `Simulator.SubSystem.FluxReconstruction.`，完整键见 4.10.4 节）

| 键 | 说明 |
|----|------|
| `Data.RiemannFlux` | `RoeFlux` / `LaxFriedrichsFlux` |
| `Data.SolutionPointDistribution / FluxPointDistribution` | `GaussLegendre` 等 |
| `Data.CorrectionFunctionComputer` + `CFactor` | `VCJH` 族（c=9.5e-4） |
| `ConvSolveCom = ConvRHSJacobAna`、`SpaceRHSJacobCom` | 解析雅可比路径 |
| `JacobianSparsity` / `FreezeJacob*` | 稀疏模式与冻结 |
| 阶次 | 经 `MeshUpgrade.PolynomialOrder = P2…P8` |
| 高阶输出 | `WriteSolutionHighOrder` |

**【输出结果】** 高阶解（解点值 + 高阶插值输出）。

**【依赖】** 物理扩展插件族（NS/Turb/MHD/MultiFluidMHD/EntropyMHD/Poisson/HyperPoisson/NEQ）；隐式需 `Petsc`（或 `FluxReconstructionPetsc`）；GPU 需 `FluxReconstructionCUDA`。

**【验证算例】** `plugins/NavierStokes/testcases/Cylinder/`（`cylinderEuler2DFR.CFcase`、`cylinderEuler2DFR-impl_P4…P8.CFcase` 等）。注意：**FR 内核插件 `FluxReconstructionMethod` 及各 FR 物理扩展插件下均无 `testcases/` 目录**（实测 CFcase 数为 0），FR 算例统一放在物理插件（NavierStokes 等）的算例目录中。

**【已知限制】** 强间断需混合/限幅（`BaseOrderBlending`、`BasePhysicality`）；非平衡扩展（NEQ 7 文件）为骨架级。

**【功能描述】** 谱差分/谱体积高阶方法内核及 NS/LES/LinEuler 扩展。

**【输出结果】** 高阶解（`.plt` 多阶输出）。

**【依赖】** `SpectralFDNavierStokes(55)/LES(23)/LinEuler(29)`；`SpectralFVNavierStokes(41)`。

**【验证算例】** `accpulse2d-*`（P1–P5 收敛族）、`cylinderLES2D-*` 等。

**【已知限制】** LES 系 SD 算例依赖滤波（`ExplicitFilters`）等外部件。

### 6.2.10 `Petsc`、`NewtonMethod`、`LUSGSMethod`——隐式求解三件套

**【功能描述】** PETSc 线性求解后端；Newton/BDF/CN 隐式推进；LU-SGS 内存友好迭代。

Simulator.SubSystem.NewtonIteratorLSS.Data.KSPType = KSPGMRES

## 6.3 插件启用方式详解

### 6.3.1 动态库模式（默认）

1. **装载**：CFcase `Simulator.Modules.Libs = libA libB …` 列出插件基名；`ModuleLoader` 逐个经 `LibLoader`（POSIX `dlopen`）装载，`ModuleRegister<MODULE>` 把库内全部 `ObjectProvider` 注册进全局 `FactoryRegistry`；
2. **搜索路径**：库名解析遵循 `DirPaths`（`--ldir` 追加搜索目录；构建产物在 `<build>/lib` 或 `src/lib` 路径下，configure 后 wrapper 脚本负责）；`--testEnv` 可诊断装载问题（第 0.3.7 节）；
3. **实例化**：装载阶段只注册不构造；configure 阶段由 `Simulator` 读取 `PhysicalModelType/SpaceMethod/ConvergenceMethod/…` 字符串，经 FactoryRegistry 实例化并绑定 `MethodData`。

> 同一插件被两个 `SubSystem` 使用：先 `registerAll` 一次，`MethodRegistry` 按方法数据分配不同实例——即"一份代码、多实例配置"。

### 6.3.2 静态单执行文件模式

`-DCF_ENABLE_SINGLEEXEC=ON`：把启用插件编译为静态库并整体链接进 `coolfluid-solver`；`apps/Solver/PluginsRegister.hh`（约 3100 行）提供**唯一注册入口** `PluginsRegister::registerAll(SafePtr<FactoryRegistry>)`（定义见 `PluginsRegister.hh:581`），由 `apps/Solver/coolfluid-solver.cxx:165` 的 `pr.registerAll(fRegistry);` 调用**一次**；其内部以 `FACTORY(fRegistry, <基类>)->regist(new ObjectProvider<实现类, 基类, 模块, 1>("<注册名>"))` 逐条注册各插件的 Provider（如 `PluginsRegister.hh:3073` 起的 `PhysicalModelDummy`）。注意：**并非"各插件模块各有一个 `registerAll` 被逐个调用"**，而是集中在这一个方法内逐条 `regist`。**无需 `Modules.Libs`**（或列表被忽略），可执行文件自足、便于移植到无动态库环境。

### 6.3.3 插件间依赖与加载顺序

- **注册与解析分离**：装载顺序只影响注册先后；跨插件引用（如 `libMutation2OLDI` 被 NEQ 的 `setup` 查询）发生在 configure/setup 阶段，因此顺序**无硬性依赖**；
- **推荐顺序**（各算例模板惯例）：网格 IO → 物理/物性库 → 方法 → 方法扩展 → 时间推进/LSS → 输出/后处理。照抄模板即可，避免"物理在方法之后"的阅读混乱；
- **多版本共存**：`Mutation2.0I` 与 `Mutation2.0.0I` 同时出现在 `Modules.Libs` 时按列表先后注册，物理化学库通过 `PhysicalChemicalLibrary` 的命名实例选择（如 FireII 的 `Mutation2OLD` 实例命名）。

### 6.3.4 编译期启用

- **逐插件开关**：每个插件对应 **`CF_BUILD_<LIBNAME>`**（如 `CF_BUILD_FINITEVOLUME`）；`tools/scripts/prepare.pl` 读取根目录 `coolfluid.conf` 的 `lib_xxx=on/off`（如 `lib_finitevolume=on`）生成这些开关（实测）；
- **默认全编译**：未显式关闭的插件默认参与构建；无法满足外部依赖的插件在 `find_package` 失败时自动跳过（并打印提示）；
- **外部依赖检测**：`CF_HAVE_*` 系列缓存变量（`CF_HAVE_PETSC/CF_HAVE_PARMETIS/CF_HAVE_CUDA/CF_HAVE_PARADE/CF_HAVE_PARALUTION` 等）由各插件的 CMake 模块（`cmake/Modules/Find*.cmake`、`AutoTemplateLoader/cmake/` 等）设置；
- **搜索路径**：`-DCF_EXTRA_SEARCH_DIRS=<dir>` 追加自定义依赖搜索（第 8.2.4 节）；
- **个人覆盖**：构建目录下 `coolfluid.cmake` 会被顶层自动 `INCLUDE`（与个人配置 `coolfluid.conf` 区分，第 8.2.4 节）——多用户共享源码树时隔离个人 `-D`；
- 编译期开关与运行期 `Modules.Libs` 的关系：**编译决定了"有没有"，CFcase 决定"用不用"**。
