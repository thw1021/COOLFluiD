## 4.1 从方程到算法：总体路线图

任何 CFD 求解器（包括 COOLFluiD 的所有方法）都遵循同一个七步链条。理解这条链，就知道每个配置项、每个类在干什么：

```
┌─ 第 3 章 ────────────────────────────────────────────────┐
│ ① 偏微分方程（PDE）：∂U/∂t + ∇·F = ∇·F_v + S              │
└──────────────────────────────────────────────────────────┘
                        ↓ 空间离散
┌─ 4.2–4.6 ───────────────────────────────────────────────┐
│ ② 半离散方程：V_i dU_i/dt = -R_i(U)                       │
│    其中 R_i = Σ_faces F̂·n A  （面通量求和）               │
│    ├─ 4.3 重构：单元平均 → 界面左右态 U_L, U_R             │
│    ├─ 4.4 通量：F̂ = RiemannSolver(U_L, U_R, n)           │
│    ├─ 4.5 粘性：F̂_v（需要梯度）                           │
│    └─ 4.6 源项：S（化学、辐射、轴对称几何）                │
└──────────────────────────────────────────────────────────┘
                        ↓ 时间离散
┌─ 4.7 ───────────────────────────────────────────────────┐
│ ③ 代数方程：显式 U^{n+1} = U^n - (Δt/V)R(U^n)            │
│             隐式 R(U^{n+1}) = 0                          │
└──────────────────────────────────────────────────────────┘
                        ↓ 线化（隐式时）
┌─ 4.8 ───────────────────────────────────────────────────┐
│ ④ 线性系统：(V/Δt + ∂R/∂U) ΔU = -R                       │
│    → BlockAccumulator 装配 → LSS（PETSc 等）求解          │
└──────────────────────────────────────────────────────────┘
                        ↓
│ ⑤ 更新：U ← U + ΔU                                       │
│ ⑥ 收敛判断：‖R‖ < tol ?                                  │
│ ⑦ 后处理：输出物理量（第 10 章）                          │
```

**两步之间的关键桥梁**：

| 环节 | 数学工具 | 代码实现 |
|------|----------|----------|
| PDE → 半离散 | 散度定理 + 面积分 | 面循环 + `_fluxSplitter->computeFlux()` |
| 单元平均 → 界面态 | 重构（多项式 + 限制器） | `_polyRec->extrapolate()` |
| 左右态 → 数值通量 | 近似 Riemann 求解器 | `RoeFlux` / `AUSMPlusUpFlux` / `HLLEFlux` |
| 半离散 → 代数 | 时间离散（BDF2/CN/RK） | `BDF2::takeStepImpl()` 等 |
| 非线性 → 线性 | Newton 线化 + 数值/解析 Jacobian | `BlockAccumulator` + `NumericalJacobian` |

## 4.2 有限体积空间离散（`CellCenterFVM`）

这是 COOLFluiD 的主力方法，也是理解其他方法的**基础模板**（RDS 在节点上做类似的事，FR 把它推广到高阶）。

### 4.2.1 数学推导：从积分方程到面通量求和

**第 1 步：对单元积分守恒律**

对任意网格单元 $\Omega_i$ 积分（以无粘为例）：

$$\int_{\Omega_i}\frac{\partial U}{\partial t}dV + \int_{\Omega_i}\nabla\cdot\mathbf{F}\,dV = 0$$

**第 2 步：散度定理把体积分变面积分**

$$V_i\frac{d\bar U_i}{dt} + \oint_{\partial\Omega_i}\mathbf{F}\cdot\mathbf{n}\,dS = 0$$

其中 $\bar U_i = \frac{1}{V_i}\int_{\Omega_i}U\,dV$ 是单元平均值（**这就是我们的未知量**，存在 `socket_states` 里），$V_i$ 是单元体积。

**第 3 步：边界积分按面离散**

单元边界由若干平面（2D 是线段）组成，每个面上用**数值通量** $\hat{\mathbf{F}}$ 近似（因为界面两侧状态不同，需要求解 Riemann 问题）：

$$V_i\frac{d\bar U_i}{dt} + \sum_{f\in\partial\Omega_i}\hat{\mathbf{F}}_f\,A_f = 0$$

**第 4 步：定义残差**

$$R_i \equiv \sum_{f\in\partial\Omega_i}\hat{\mathbf{F}}_f A_f \quad\Rightarrow\quad \frac{d\bar U_i}{dt} = -\frac{R_i}{V_i}$$

于是定常解就是 $R_i=0$。**残差 $R_i$ 是贯穿全书的核心量**，代码中即 `socket_rhs`（DataHandle，按 `(stateID, iEq, nbEqs)` 索引）。

**第 5 步：加入粘性、源项**

$$R_i = \underbrace{\sum_f \hat{\mathbf{F}}_f A_f}_{\text{对流，双曲}} - \underbrace{\sum_f \hat{\mathbf{F}}_{v,f}A_f}_{\text{粘性，抛物}} - \underbrace{S_i V_i}_{\text{源项}}$$

> **为什么对流和粘性用不同的数值处理？** 对流项是双曲型（有方向性——信息从上游来），必须**迎风**处理；粘性项是抛物型（各向同性扩散），用**中心差分**即可。代码中二者是独立的两个通量对象（`_fluxSplitter` 与 `_diffusiveFlux`），见 4.2.3。

### 4.2.2 算法伪代码

```
算法：FVM 空间残差计算（半离散）
输入：当前解 U（单元平均），网格（面、法向、面积、体积）
输出：残差 R_i、时间步系数 updateCoeff_i

1.  R_i ← 0;  updateCoeff_i ← 0                    # 清零
2.  计算单元梯度 ∇U_i（若需二阶，见 4.3）；外推到节点（若需粘性）
3.  for 每个 TRS（拓扑区域集）:                     # InnerFaces, 各边界 TRS...
4.      if TRS 是"PartitionFaces"/"InnerCells"/豁免列表: continue
5.      for TRS 中每个面 f:
6.          (i, j) ← 面的左右单元;  n ← 单位法向;  A ← 面面积
7.          if f 是边界面:
8.              _currBC->computeFlux(_flux)        # BC 写虚拟态后算通量
9.          else:
10.             (U_L, U_R) ← 重构(i, j, ∇U)        # 4.3：分片常数或线性+限制
11.             物理数据解码 pdata ← (ρ,u,v,p,T,H,a)   # 3.1.4
12.             _flux ← RiemannFlux(U_L, U_R, n)   # 4.4
13.         if 有粘性:
14.             ∇U_f ← 面控制体梯度(节点值)          # 4.5
15.             _dFlux ← ViscousFlux(∇U_f, μ, k) * A
16.             _flux ← _flux - _dFlux               # 注意减号！
17.         if 有源项: _flux ← _flux - S*A            # 4.6（或按体积加）
18.         # 残差累加：左单元减、右单元加
19.         R_i ← R_i - _flux;   R_j ← R_j + _flux   # 面的法向由 i 指向 j
20.         updateCoeff_i += max(λ_max, 0)*A        # 谱半径，供 Δt 用（4.7.4）
21.         updateCoeff_j += max(λ_max, 0)*A
22.  return R, updateCoeff
```

**伪代码第 19 行的符号约定**：法向 $\mathbf{n}$ 由左单元指向右单元，因此流出左单元的通量对左单元是"损失"（$-$），对右单元是"收入"（$+$）。这正是代码 `rhs(firstStateID,...) -= ...; rhs(lastStateID,...) += ...` 的含义。

```cpp
void FVMCC_ComputeRHS::updateRHS()
{
  if (getMethodData().isAxisymmetric()) {          // 轴对称：需要半径因子
    const Node* node0 = _currFace->getNode(0);
    const Node* node1 = _currFace->getNode(1);
    _rMid  = 0.5*std::abs((*node0)[YY] + (*node1)[YY]);      // 面中点半径 r
    _invr[0] = 1./std::abs(_currFace->getState(0)->getCoordinates()[YY]);   // 1/r_i
  }

  const CFreal coeff = (getResFactor()*_rMid);    // resFactor：时间离散的系数（4.7）
  _rFlux = coeff*_flux;                           // 带系数与轴对称因子的通量

  const CFuint nbEqs = PhysicalModelStack::getActive()->getNbEq();
  State* const firstState  = _currFace->getState(0);
  const CFuint firstStateID = firstState->getLocalID();
  DataHandle<CFreal> rhs = socket_rhs.getDataHandle();

  for (CFuint iEq = 0; iEq < nbEqs; ++iEq) {
    rhs(firstStateID, iEq, nbEqs) -= _rFlux[iEq]*_invr[0];     // R_i -= F·n A (+1/r 轴对称)
  }

  State* const lastState = _currFace->getState(1);
  if (!lastState->isGhost()) {                    // 右单元不是 ghost 才累加
    const CFuint lastStateID = lastState->getLocalID();
    cf_assert(firstStateID < lastStateID);
    for (CFuint iEq = 0; iEq < nbEqs; ++iEq) {
      rhs(lastStateID, iEq, nbEqs) += _rFlux[iEq]*_invr[1];   // R_j += F·n A
    }
  }
}
```

> ⚠️ **旧版手册此处有误**：曾把右单元的累加写成注释掉的形式（"// rhs(lastStateID...) += ..."），容易让人误以为代码只对左单元累加。**实际代码（:492-499）确实对右单元执行 `+=`**，否则内部面的通量不会成对抵消、全局不守恒。这正是 4.2.2 伪代码第 19 行 `R_i ← R_i − F; R_j ← R_j + F` 与本节开头"代码 `rhs(firstStateID,...) -= ...; rhs(lastStateID,...) += ...`"的落点。
>
> 另有两点实现细节：
> - `_invr[1]`（右单元的 $1/r$）在**轴对称分支内**（:467）与 `_invr[0]` 一起被赋值；非轴对称时二者保持默认的 `1.0`，故 `_invr` 不影响普通算例。
> - 累加前有 `cf_assert(firstStateID < lastStateID)`（:495）——这是内部面"左 ID < 右 ID"的不变式，Debug 构建下可据此发现面的定向错误。

## 4.3 重构与限制器：二阶精度是怎么来的

### 4.3.1 问题：分片常数只有一阶精度

若直接用单元平均值作为界面值（$U_L=\bar U_i$，$U_R=\bar U_j$），格式只有**一阶精度**，数值耗散极大——激波被抹成七八个网格宽，边界层完全算不准。

**解法：重构（reconstruction）**。在每个单元内用多项式近似解：

$$U_i(\mathbf{x}) = \bar U_i + \nabla U_i\cdot(\mathbf{x}-\mathbf{x}_i) + O(\Delta^2)$$

于是界面值：

$$U_L = \bar U_i + \phi_i\,\nabla U_i\cdot(\mathbf{x}_f-\mathbf{x}_i),\qquad U_R = \bar U_j + \phi_j\,\nabla U_j\cdot(\mathbf{x}_f-\mathbf{x}_j)$$

其中 $\phi\in[0,1]$ 是**限制器**（limiter）——这是 Godunov 定理的必然要求：**任何高于一阶的线性格式都会在间断附近产生振荡**，必须用非线性限制器抑制。

### 4.3.2 梯度的计算

**(1) Green-Gauss 法**（基于散度定理，代码 `ComputeVariablesDerivatives`）

$$\nabla U_i \approx \frac{1}{V_i}\oint_{\partial\Omega_i}U\mathbf{n}\,dS \approx \frac{1}{V_i}\sum_{f}\bar U_f\mathbf{n}_f A_f$$

$\bar U_f$ 取面两侧单元的平均。**优点**：守恒、简单；**缺点**：网格歪斜时精度下降（需"修正"）。

**(2) 最小二乘法**（代码 `LeastSquareP1PolyRec2D`，注册名 `LinearLS2D`）

要求重构在模板内所有邻居上误差最小：

$$\min_{\nabla U_i}\sum_{j\in\text{stencil}} w_{ij}\left[\bar U_i + \nabla U_i\cdot(\mathbf{x}_j-\mathbf{x}_i) - \bar U_j\right]^2$$

解一个小型最小二乘问题（2D 是 $2\times2$ 法方程，3D 是 $3\times3$）。**优点**：非结构网格上精度好、对网格质量不敏感；**缺点**：要解小方程组。

**模板选择**（CFcase `LeastSquareP1Setup.stencil`）：

模板不是枚举值，而是 **`ComputeStencil` 的 Provider 注册名**（`LeastSquareP1Setup.cxx:157` 用 `FACTORY_GET_PROVIDER(getFactoryRegistry(), ComputeStencil, _stencilType)` 动态创建）。实测全表（`plugins/FiniteVolume/`）：

| 注册名 | 实现类 | 含义 | 何时用 |
|--------|--------|------|--------|
| `FaceVertex` | `ComputeFaceVertexNeighbors.cxx:25` | 面相邻单元 + 顶点相邻单元 | 默认，通用 |
| `FaceVertexPlusGhost` | `ComputeFaceVertexNeighborsPlusGhost.cxx:27` | 再加上 ghost 单元 | 边界处模板更完整 |
| `FaceBVertex` | `ComputeFaceBVertexNeighbors.cxx:26` | 含**边界**顶点邻居 | 边界精度要求高时 |
| `FaceEdge` | `ComputeFaceEdgeNeighbors.cxx:25` | 面相邻 + 边相邻 | 介于 `Face` 与 `FaceVertex` 之间 |
| `Face` | `ComputeFaceNeighbors.cxx:26` | 仅面相邻单元（最紧凑） | 最省内存，精度略低 |

法方程规模与维度：`getDim()` 决定（2D 为 $2\times2$，3D 为 $3\times3$），与模板大小无关；模板越宽只增加求和项数与内存，不改变法方程维数。

### 4.3.3 限制器：Barth–Jespersen 与 Venkatakrishnan

**(1) Barth–Jespersen**（`plugins/FiniteVolume/BarthJesp.cxx:60`，注册名 `BarthJesp2D/3D`）

原则：**重构后的界面值不能超出邻居的极值范围**（不产生新极值 → 单调）。

$$\phi_i = \min_{f\in\partial\Omega_i}\begin{cases}\min\left(1,\dfrac{U_i^{max}-\bar U_i}{U_f-\bar U_i}\right), & U_f>\bar U_i\\[6pt]\min\left(1,\dfrac{U_i^{min}-\bar U_i}{U_f-\bar U_i}\right), & U_f<\bar U_i\\[6pt]1, & U_f=\bar U_i\end{cases}$$

其中 $U_i^{max/min}$ 取模板内（含自身）的最大/最小值。

**源码对照**：

```cpp

                      GeometricEntity* const cell, CFreal* limiterValue)
{
  DataHandle<CFreal> uX = socket_uX.getDataHandle();     // ∂U/∂x

    }
    // ... 逐面计算 U_f 并与 min0/max0 比较，得到 limiterValue[iVar]

```

**(2) Venkatakrishnan**（`Venktn2D/3D`）

Barth 限制器在极值点处会"卡住"收敛（因为 $\phi\to0$，格式退化为一阶）。Venkatakrishnan 引入与网格尺度相关的阈值，使限制器在光滑区不完全关闭：

$$\phi_i = \min_f \frac{\Delta_+^2 + \epsilon^2 + 2\Delta_+\Delta_-}{\Delta_+^2 + 2\Delta_-^2 + \Delta_+\Delta_- + \epsilon^2},\qquad \epsilon^2 = (c_{eps}\,\Delta x)^3$$

参数 `coeffEps` 即上式 $c_{eps}$，**越小越接近硬限制（Barth），越大越光滑但可能过冲**。

> **经验**：Barth 系更"硬"（收敛慢、无过冲、更稳）；Venkatakrishnan 系更光滑（收敛快，$\texttt{coeffEps}$ 调得太大会过冲）。

### 4.3.4 MUSCL 一维重构源码（`MUSCLPolyRec`）

沿"左右单元连线"方向做一维重构，需要四个单元（《 $U_{i-1},U_i,U_{i+1},U_{i+2}$ 》）。

**源码对照**（`plugins/FiniteVolume/MUSCLPolyRec.cxx:104`）：

```cpp
void MUSCLPolyRec::extrapolateInner(GeometricEntity* const face)
{
  // 模板排列：  U_i-1   U_i    U_i+1   U_i+2
  //             c[2]    c[0]   c[1]    c[3]
  const vector<State*>& cs = *getStencil(faceID, false);
  cf_assert (cs.size() == 4);

  _drUlUll = (*cs[0]) - (*cs[2]);      // Δ_-  = U_i - U_{i-1}
  _drUrUl  = (*cs[1]) - (*cs[0]);      // Δ_c  = U_{i+1} - U_i
  _drUrrUr = (*cs[3]) - (*cs[1]);      // Δ_+  = U_{i+2} - U_{i+1}

  for (CFuint iVar = 0; iVar < nbEqs; ++iVar) {
    // 光滑性比值（用于斜率限制器，如 van Leer / van Albada）
    _r1[iVar] = (std::abs(_drUrUl[iVar]) > 0.) ? _drUlUll[iVar]/_drUrUl[iVar] : 0.0;
    _r2[iVar] = (std::abs(_drUrrUr[iVar]) > 0.) ? _drUrUl[iVar]/_drUrrUr[iVar] : 0.0;
  }
  // ... 用 _r1/_r2 通过限制器函数 ψ(r) 得到斜率，再外推到界面
}
```

| 代码变量 | 数学符号 | 含义 |
|----------|----------|------|
| `_drUlUll` | $\Delta_- = U_i-U_{i-1}$ | 后向差分 |
| `_drUrUl` | $\Delta_c = U_{i+1}-U_i$ | 中心差分（穿过当前面） |
| `_drUrrUr` | $\Delta_+ = U_{i+2}-U_{i+1}$ | 前向差分 |
| `_r1, _r2` | $r$ | 光滑性指示量：接近 1 表示光滑，远离 1 表示有间断 |

**为什么需要 $U_{i-1}$ 和 $U_{i+2}$？** 因为要判断"当前面附近是否光滑"。只有两个点无法区分"斜坡"和"间断"。

### 4.3.5 重构算法伪代码

```
算法：二阶 MUSCL 重构（对单个面 f，左右单元 i、j）
1.  取模板：{i-1, i, j, j+1}（沿面法向方向的四个单元）
2.  计算差分 Δ_-, Δ_c, Δ_+
3.  光滑比 r ← Δ_c / Δ_- （或按限制器定义）
4.  斜率 ψ ← limiter(r)      # minmod: max(0,min(1,r)); van Leer: (r+|r|)/(1+|r|)
5.  梯度修正：∇U ← ψ·∇U      # 或直接用限制器值 φ 乘梯度
6.  U_L ← Ū_i + φ_i ∇U_i·(x_f - x_i)
7.  U_R ← Ū_j + φ_j ∇U_j·(x_f - x_j)
8.  return U_L, U_R
```

### 4.3.6 关键参数：如何"先爬 CFL 再开限制器"

限制器虽保证稳定，但会拖慢收敛（尤其 Barth）。工程做法（见 `cyl_Pg_M15_FVM_1st2nd.CFcase`）：

**这三个参数的真实语义与"先无限制、后限制"的直觉相反**，必须以源码为准。判定逻辑在 `plugins/FiniteVolume/FVMCC_PolyRec.cxx:145-163`（`computeFaceLimiter()`）：

```cpp

}
```

| 参数 | 源码默认 | 真实语义 |
|------|----------|----------|
| `limitIter` | `1000000000`（`FVMCC_PolyRec.cxx:58`，即"几乎永不触发分支 B"） | 当 `iter < limitIter` 时走**分支 A**：限制器每步**从 1.0 重新计算**（可随时放松回 1）；一旦 `iter >= limitIter` 转入**分支 B** |
| `limitRes` | 同上判定 | 当 `residual > limitRes` 时走**分支 A**；一旦 `residual <= limitRes` 转入**分支 B**。注意与 `limitIter` 是**逻辑与**关系：只有二者同时满足才在分支 A |
| `FreezeLimiter`（`freezeLimiter`） | `false` | **只在分支 B 生效**：`true` 时连 `min` 收紧也不做，限制器彻底冻结 |
| `gradientFactor` | `1.0` | 梯度的整体缩放系数。**它不是 `LinearLS2D` 的直接标量选项**，而是由基类的 `Def` / `Vars`（`FVMCC_PolyRec.cxx:25-26`）函数机制驱动：见 `prepareReconstruction()`（:108-116），当 `Vars = i` 时把迭代号代入 `Def` 表达式求值赋给 `_gradientFactor`；另可按变量逐个覆盖（`gradientCoeff`，`LeastSquareP1PolyRec2D.cxx:195-196` 注明"gradientCoeff prevails on the interactive gradientFactor"） |

**分支 B 到底在做什么**：它把限制器变成**单调非增序列**（`newLimiter = min(old, new)`），即限制越来越紧且不再放松。其工程目的是——在收敛后期抑制限制器在极值点反复开关造成的残差停滞（见 4.19.3 平台期），让解能收敛到机器精度。因此这段逻辑应理解为"**先每步重算（可放松）、后单调收紧（可收敛）**"，而不是"先不限制、后限制"。

**正确写法示例**：


## 4.4 界面通量：近似 Riemann 求解器

### 4.4.1 问题：界面两侧状态不同

重构给出 $U_L, U_R$，但方程需要**唯一**的界面通量。数学上这是一个 **Riemann 问题**（3.3.4 节）。数值通量函数：

$$\hat{\mathbf F} = \hat{\mathbf F}(U_L, U_R, \mathbf n)$$

**相容性要求**：$U_L=U_R=U$ 时，$\hat{\mathbf F}=\mathbf F(U)\cdot\mathbf n$（否则格式不一致，会算错）。

### 4.4.2 中心格式 + 人工耗散（最简单）

$$\hat{\mathbf F} = \frac{1}{2}\left[\mathbf F(U_L)+\mathbf F(U_R)\right]\cdot\mathbf n - \underbrace{d}_{\text{人工耗散}}$$

问题：耗散量 $d$ 需要人工调（Jameson 型二阶/四阶人工粘性）。**优点**：鲁棒（常用于初始启动）；**缺点**：耗散系数靠经验，激波分辨率不如迎风格式。代码：`Centred`。

### 4.4.3 Roe 格式（最经典的迎风格式）

**核心思想**：用 Roe 平均态 $\tilde U$ 把非线性问题**线性化**，然后精确求解这个线性化问题。

**Roe 的三个条件**（U 性质）：

1. $A(\tilde U)$ 有实特征值与完备特征向量（双曲性）；
2. **相容性**：$\mathbf F(U_R)-\mathbf F(U_L) = A(\tilde U)(U_R-U_L)$（关键！保证激波位置正确）；
3. 当 $U_L\to U_R$ 时 $A(\tilde U)\to A(U)$。

**Roe 平均**（完全气体，$\rho$ 用几何平均）：

$$\tilde\rho = \sqrt{\rho_L\rho_R},\quad
\tilde{\mathbf u} = \frac{\sqrt{\rho_L}\mathbf u_L+\sqrt{\rho_R}\mathbf u_R}{\sqrt{\rho_L}+\sqrt{\rho_R}},\quad
\tilde H = \frac{\sqrt{\rho_L}H_L+\sqrt{\rho_R}H_R}{\sqrt{\rho_L}+\sqrt{\rho_R}}$$

**Roe 通量公式**：

$$\boxed{\hat{\mathbf F} = \frac{1}{2}\left[\mathbf F(U_L)+\mathbf F(U_R)\right]\cdot\mathbf n - \frac{1}{2}R\lvert\Lambda\rvert R^{-1}(U_R-U_L)}$$

第一项是中心部分（平均输运），第二项是**迎风耗散**——$|A|=R|\Lambda|R^{-1}$，特征值绝对值越大耗散越强，方向由特征向量决定。**物理直觉**：耗散正比于"信息传播速度"，这正是迎风的本质。

**源码对照**（`plugins/FiniteVolume/RoeFlux.cxx:120`）：

```cpp
void RoeFlux::compute(RealVector& result)
{
  // ① 取重构得到的左右状态
  _statesLR[0] = &polyRec->getCurrLeftState();    // U_L
  _statesLR[1] = &polyRec->getCurrRightState();   // U_R

  // ② 变量集转换（若 UpdateVar ≠ SolutionVar）
  if (!getMethodData().reconstructSolVars()) {
    _solutionStates = getMethodData().getUpdateToSolutionVecTrans()->transform(&_statesLR);
  } else {
    _solutionStates = &_statesLR;
  }

  linearize();                                    // ③ 用 LinearVar 做 Roe 平均线化

  const RealVector& unitNormal = getMethodData().getUnitNormal();   // n

  // ④ 计算线化 Jacobian 的特征向量与特征值
  solutionVarSet->computeEigenValuesVectors(_rightEv,   // R
                                            _leftEv,    // R⁻¹
                                            _eValues,   // Λ
                                            unitNormal);
  setAbsEigenValues();                            // ⑤ |Λ|（含熵修正/carbuncle 修复）

  // ⑥ 中心部分：F(U_L) + F(U_R)
  vector<RealVector>& pdata = polyRec->getExtrapolatedPhysicaData();
  _sumFlux  = updateVarSet->getFlux()(pdata[0], unitNormal);   // F(U_L)·n
  _sumFlux += updateVarSet->getFlux()(pdata[1], unitNormal);   // F(U_R)·n

  const State& stateL = *(*_solutionStates)[0];
  const State& stateR = *(*_solutionStates)[1];

  // ⑦ Roe 通量：0.5*(F_L+F_R) - 0.5*|A|*(U_R-U_L)
  result = 0.5*(_sumFlux - getReductionCoeff()*(_rightEv*(_absEvalues*_leftEv))*(stateR - stateL));
```

### 4.4.4 熵修正与 carbuncle 修复

**问题 1：膨胀激波**。声速点附近（$\lambda=u\pm a\approx0$），Roe 的耗散 $\lvert\lambda\rvert\to0$，不足以抑制非物理解。

**修正**（Harten 型）：把过小的特征值"抬起来"

$$\lvert\lambda\rvert_{mod} = \begin{cases}\lvert\lambda\rvert, & \lvert\lambda\rvert \ge \epsilon\\ \dfrac{\lambda^2+\epsilon^2}{2\epsilon}, & \lvert\lambda\rvert < \epsilon\end{cases},\qquad \epsilon\sim \delta(\lvert u\rvert + a)$$

**问题 2：Carbuncle**。强激波（$M>5$）与网格对齐时，Roe 格式会算出非物理的"红玉"状激波畸变。修正思路是**给剪切波加耗散**（Sanders 等）。

**代码落点**：`RoeFlux::setAbsEigenValues()`（第 199 行）——注释明确写着"the implementation of this function changes if there are entropy or carbuncle fixes"。

| 注册名 | 修正类型 | 配置 |
|--------|----------|------|
| `Roe` | 基线 Roe | — |
| `RoeEntropyFix` / `RoeT4` / `RoeVLPA` | 不同熵修正 | `entropyFixID = 1/2/3` |
| `RoeSA` | Sanders 型 **carbuncle 修复** | M15 圆柱算例所用 |
| `RoeALE` | 动网格变体（含网格速度） | 4.14 |
| `RoeTurb` | 湍流变量扩展 | 配 SA/k-ω |

### 4.4.5 HLL / HLLE 族

**思路**：不求全部波，只分辨最快的两（三）个波。用波速估计 $S_L,S_R$：

$$\hat{\mathbf F} = \begin{cases}\mathbf F(U_L)\cdot\mathbf n, & S_L \ge 0\\ \dfrac{S_R\mathbf F(U_L)-S_L\mathbf F(U_R)+S_LS_R(U_R-U_L)}{S_R-S_L}\cdot\mathbf n, & S_L<0<S_R\\ \mathbf F(U_R)\cdot\mathbf n, & S_R\le 0\end{cases}$$

**波速估计**（简单实用）：$S_L = \min(u_{n,L}-a_L,\,u_{n,R}-a_R)$，$S_R = \max(u_{n,L}+a_L,\,u_{n,R}+a_R)$。HLLE 用 Roe 平均改进波速估计，减少中间态的耗散。

**优点**：鲁棒（保证正密度/正压）、无 carbuncle、实现简单；**缺点**：接触间断和剪切层耗散大（分辨不出中间波）。代码：`HLL`、`HLLE1D`/`HLLE2D`/`HLLE3D`（按维度注册的模板实例化名）；RDS（FluctSplit）侧另有 `SysHLLC`（HLLC，恢复接触波，见 4.9）。

### 4.4.6 AUSM 族（工程主流）

**思路**：把通量拆成**对流项**（随质量流输运）与**压力项**分别处理：

$$\hat{\mathbf F} = \underbrace{\dot m\begin{pmatrix}1\\u\\v\\H\end{pmatrix}}_{\text{对流（迎风）}} + \underbrace{\begin{pmatrix}0\\ p\,n_x\\ p\,n_y\\ 0\end{pmatrix}}_{\text{压力（中心）}}$$

关键在**质量通量** $\dot m$ 与**界面压力** $p$ 的分裂函数（依赖马赫数）：

$$M_{1/2} = \mathcal{M}^+_{(1)}(M_L) + \mathcal{M}^-_{(1)}(M_R),\qquad p_{1/2} = \mathcal{P}^+_{(5)}p_L + \mathcal{P}^-_{(5)}p_R$$

**AUSM+-up 的优势**：增加压力耗散项，使其在全马赫数范围（$M\sim10^{-3}$ 到 $M>10$）都保持低耗散——**低马赫流动的预条件隐含在格式中**，无需额外预处理。这是宽马赫范围工程问题的首选。

## 4.5 粘性（扩散）通量离散

### 4.5.1 数学：为什么粘性项需要梯度

粘性通量（3.2.2）：

$$\mathbf F_v\cdot\mathbf n = \begin{pmatrix}0\\ \tau_{xx}n_x+\tau_{xy}n_y\\ \tau_{xy}n_x+\tau_{yy}n_y\\ (u\tau_{xx}+v\tau_{xy}-q_x)n_x + (u\tau_{xy}+v\tau_{yy}-q_y)n_y\end{pmatrix}$$

而 $\tau_{ij}$ 与 $\mathbf q$ **都依赖速度和温度的梯度**：

$$\tau_{ij} = \mu\left(\partial_j u_i + \partial_i u_j - \tfrac23\partial_k u_k\,\delta_{ij}\right),\qquad \mathbf q = -k\nabla T$$

**这就是粘性项与对流项的根本区别**：对流项只需界面左右两个状态值（$U_L,U_R$），粘性项需要**面心处的梯度**。这是粘性计算更复杂、模板更宽的根源。

### 4.5.2 面梯度的计算：面控制体（face control volume）

标准做法：构造一个跨越界面的小控制体（由界面两端节点 + 左右单元中心构成），在其上用散度定理：

$$\nabla\phi|_f \approx \frac{1}{V_{CV}}\oint_{\partial CV}\phi\,\mathbf n\,dS \approx \frac{1}{V_{CV}}\sum_{faces\ of\ CV}\bar\phi\,\mathbf n\,A$$

**纯 Green-Gauss 在歪斜网格上不精确**，故实际用"修正"版本——`DerivativeComputer` 族（注册名 `Corrected2D`、`CorrectedGG2D/3D`）：先用最小二乘或节点外推估计节点值，再做 Green-Gauss 积分。

**节点值从哪来？** 单元中心值需要外推到节点，策略由 `Data.NodalExtrapolation` 控制：

| 策略 | 原理 |
|------|------|
| `HolmesConnell` | Holmes–Connell 加权平均（考虑距离与体积权重） |
| `DistanceBasedExtrapolator` | 按距离倒数加权 |

### 4.5.3 源码对照：`NSFlux::computeFlux()`

**位置**：`plugins/FiniteVolume/NSFlux.ci:59`（模板类 `NSFlux<DIFFVS>`，注册名 `"NavierStokes"`）

**(1) 构造面控制体并计算梯度**


| 代码 | 数学含义 |
|------|----------|
| `computeControlVolume` | 确定面控制体的顶点（左/右单元中心 + 面端点） |

**(2) 组装粘性通量并计入面积**

**(3) 粘性对时间步的贡献**

```cpp

  const CFreal nu = _diffVar->getCurrDynViscosity()/_diffVar->getDensity(_avState);        // ν = μ/ρ
  const CFreal diffUpdateCoeff = nu*faceArea*faceArea/(derivComputer->getControlVolume()); // ν A²/V
```

>
> 另注：`NSFlux<DIFFVS>::computeFlux` 的其余部分（`computeControlVolume` / `setGradientVars` / `computeGradients` / `computeAverageValues`）中，只有 `computeControlVolume` 与轴对称半径 `_radius` 的计算被包在 `if (!isPerturb)`（:77-100）内——因为做 Jacobian 有限差分扰动时控制体与半径不随扰动改变，无需重算；而 `setGradientVars` / `computeGradients` / `computeAverageValues` 在扰动时**照常执行**（:105-111）。这与 4.8.2 所述"扰动模式跳过与 Jacobian 无关的副作用"是一致的：跳过的是"几何相关"而非"状态相关"的计算。

**数学含义**：显式格式的粘性稳定性条件为 $\Delta t \le \dfrac{\Delta x^2}{2\nu}$（抛物型 CFL）。写成 $\nu A^2/V$ 的形式是因为在一般非结构单元上 $A^2/V$ 就是"等效 $\Delta x$ 的倒数尺度"——**这个量与对流的 $\lambda_{max}A$ 量纲相同**，可以直接相加进入 `updateCoeff`（4.7.4 节）。

### 4.5.4 粘性项算法伪代码

```
算法：粘性残差贡献（单个面 f）
1.  构造面控制体（左右单元中心 + 面端点）
2.  节点值外推：U_cell → U_node（HolmesConnell 或距离加权）       # 预处理，每步一次
3.  (u,v,T) ← 面控制体各顶点的原始变量
4.  (∇u, ∇v, ∇T) ← GreenGauss 或修正梯度（DerivativeComputer）
5.  Ū_f ← 面心平均状态
6.  (μ, k) ← 物性库(Ū_f)                       # Sutherland 或常数，Pr 关联 k=μ c_p/Pr
7.  τ_ij ← μ(∂_j u_i + ∂_i u_j - ⅔ ∂_k u_k δ_ij)      # 3.2.2
8.  q ← -k ∇T
9.  F̂_v ← [0, τ·n, (u·τ - q)·n]ᵀ
10. R_i ← R_i + F̂_v A;   R_j ← R_j - F̂_v A          # 注意：粘性项符号与对流相反
11. updateCoeff_i,j += ν A² / V                       # 粘性稳定性贡献
```

### 4.6.2 轴对称为什么需要特殊处理

轴对称流动（$x$-$r$ 平面，绕 $x$ 轴旋转对称）的控制方程多出几何项。把二维方程当作轴对称求解时，控制体是"旋转体"，体积元 $dV = r\,dr\,dx$（而非 $dr\,dx$）。因此：

$$\frac{d}{dt}\int r\,U\,dr\,dx + \oint r\,\mathbf F\cdot\mathbf n\,dS = \int S\,r\,dr\,dx$$

离散后每个面上带半径因子 $r_{face}$，每个单元的残差要除以 $r_i$——**这正是 `updateRHS()` 中 `_rMid`（面半径）与 `_invr`（$1/r_{state}$）的作用**（4.2.3 第 5 段）。此外周向速度（$w$）的动量方程会多出源项。

**配置**：`Data.NavierStokes.isAxisymm = true`；代码在 `isAxisymmetric()` 为真时切换 `computeAxiUpFactors()` 等分支。

## 4.7 时间推进：从半离散 ODE 到代数方程

### 4.7.1 半离散方程：一个巨型 ODE 系统

空间离散后（4.2），每个单元得到一个 ODE：

$$V_i\frac{dU_i}{dt} = -R_i(U),\qquad i=1..N_{cells}$$

整个流场是一个 $N_{cells}\times N_{eq}$ 维的 ODE 系统。**时间推进就是求解这个 ODE 系统**——定常问题求 $t\to\infty$ 的稳态解（此时 $R=0$），非定常问题求每个时刻的解。

### 4.7.2 显式方法：简单但受 CFL 限制

**前向 Euler**：

$$U^{n+1} = U^n - \frac{\Delta t}{V}R(U^n)$$

**稳定性条件（CFL 条件）**：

$$\Delta t \le \mathrm{CFL}\cdot\min_i\left(\frac{V_i}{\sum_f \lambda_{max}A_f}\right),\qquad \mathrm{CFL}<1\ \text{（显式）}$$

若含粘性，还要满足 $\Delta t\le \min_i V_i/(\nu A^2/V_i)$ 类约束（4.5.3）。

**物理直觉**：CFL 条件要求"一个时间步内，信息传播距离不超过一个单元"——这是数值稳定性的硬约束，**与精度无关**。

**Runge–Kutta**：多级（RK2/RK3/RK4）可放宽 CFL 并提精度。`RKLS`（低存储 RK）是高阶方法（SD/SV/FR）的标配，因为高阶格式内存紧张。

**局限**：网格越细，$\Delta t$ 越小（$\Delta t\propto\Delta x$），且刚性问题（NEQ 化学源项、粘性边界层）要求极小 $\Delta t$ → **定常问题可能要几十万步**。这是隐式的动机。

### 4.7.3 隐式方法：解非线性方程组

**后向 Euler**：

$$V\frac{U^{n+1}-U^n}{\Delta t} + R(U^{n+1}) = 0$$

未知量 $U^{n+1}$ 出现在 $R$ 内部 → 非线性方程组，用 **Newton 迭代**求解：

设 $U^{(k)}$ 为第 $k$ 次迭代值，令 $U^{(k+1)}=U^{(k)}+\Delta U$，对 $R$ 做一阶展开：

$$R(U^{(k)}+\Delta U) \approx R(U^{(k)}) + \underbrace{\frac{\partial R}{\partial U}}_{J}\Delta U$$

代入并整理得**线性系统**：

$$\boxed{\left(\frac{V}{\Delta t}I + J\right)\Delta U = -R(U^{(k)}) - \frac{V}{\Delta t}(U^{(k)}-U^n)}$$

左端矩阵叫 **Jacobian 矩阵**（$J=\partial R/\partial U$，代码中由 `BlockAccumulator` 装配，见 4.8），$V/\Delta t$ 项叫**时间项**（对角阵，由 `ComputeTimeRHS` 命令加入）。

**Newton 迭代伪代码**：

```
算法：隐式时间步（后向 Euler + Newton）
1.  U^(0) ← U^n
2.  for k = 0, 1, 2, ... until 收敛:
3.      R ← ComputeRHS(U^(k))                    # 4.2 空间残差
4.      J ← ComputeJacobian(U^(k))               # 4.8（可冻结：见下面 freezeJacobian）
5.      组装 A ← V/Δt·I + J；b ← -R - V/Δt·(U^(k) - U^n)
6.      解 A·ΔU = b                              # LSS：PETSc GMRES/ILU 等
7.      U^(k+1) ← U^(k) + ΔU                     #（可加松弛：ΔU·ω）
8.      if ‖ΔU‖ < tol: break
9.  U^{n+1} ← U^(k+1)
```

**隐式的好处**：CFL 可以远大于 1（10、100、甚至 $\to\infty$），定常问题几十~几百步即可收敛。**代价**：每步要装配并求解大型稀疏线性系统（内存与时间）。

### 4.7.4 CFL 与当地时间步

**当地时间步（Local Time Stepping）**：定常问题不需要时间精确，每个单元可用自己的 $\Delta t_i$：

$$\Delta t_i = \mathrm{CFL}\cdot\frac{V_i}{\underbrace{\sum_f\lambda_{max}A_f}_{\texttt{updateCoeff}_i} + \underbrace{\sum_f \nu A^2/V}_{\text{粘性贡献}}}$$

这就是 `socket_updateCoeff` 的用途——**它在通量计算时顺带累加（4.4.3 第 3 段、4.5.3 第 3 段），供时间步计算使用**。

**代码落点**（`plugins/FluctSplit/PseudoSteadyTimeRhs.cxx:81`，同类逻辑在 FVM 侧一致）：

```cpp
void PseudoSteadyTimeRhs::execute()
{
  DataHandle<CFreal> rhs         = socket_rhs.getDataHandle();
  DataHandle<CFreal> updateCoeff = socket_updateCoeff.getDataHandle();
  SafePtr<LSSMatrix> jacobMatrix = _lss->getMatrix();
  const CFreal cfl = getMethodData().getCFL()->getCFLValue();

  for (CFuint iState = 0; iState < nbStates; ++iState) {
    const CFreal diagValue = updateCoeff[iState]/cfl;   // (Σ λ A)/CFL = V/Δt
    // ① 把 diagValue 加到 Jacobian 对角线（时间项贡献）
    // ② 把 diagValue*(U^n - U^(k)) 加到残差（时间项右端）
  }
}
```

**关键等式**：$\dfrac{V}{\Delta t} = \dfrac{\sum_f\lambda_{max}A_f}{\mathrm{CFL}}$ = `updateCoeff/cfl`。**这解释了为什么 CFL 越大、时间项对角越小、越接近纯 Newton（定常）求解**；CFL 小时则是时间精确的推进。

**CFL 爬升策略**：初期用小 CFL（启动稳定），后期放大（加速收敛）。配置：

```bash

```

（以上为 `plugins/NavierStokes/testcases/Cylinder/cyl_Pg_M15_FVM_1st2nd.CFcase` 的**逐字原文**。⚠️ 旧版给出的是经简化的示意表达式 `if(i<600,0.7,min(1e6,cfl*1.05))`，与实测不符；请以原文为准。）

其中 `i` 是迭代号，`cfl` 是上一次的 CFL 值（**自引用**——可以写成指数增长）；`^` 为幂运算符。固定值则用 `ComputeCFL = Interactive` + `CFL.Interactive.CFL = 1.0`（该算例中被注释掉的那行即此用法）。

### 4.7.5 BDF2 / Crank–Nicolson：时间精确格式

**BDF2（二阶后向差分）**：

$$\frac{3U^{n+1}-4U^{n}+U^{n-1}}{2\Delta t} = -\frac{R(U^{n+1})}{V}$$

系数 $3/2, -2, 1/2$ 来自对 $\partial U/\partial t$ 的二阶后向差分。**变步长**时系数随之变化——这正是源码中 $\alpha,\xi,\theta$ 的来源：

**源码对照**（`plugins/NewtonMethod/BDF2.cxx:101`）：

```cpp
void BDF2::takeStepImpl()
{
  prepare();                                       // 备份 U^n, U^{n-1}
  const CFreal newDT = subSysStatus->getDT();      // Δt^{n+1}
  const CFreal oldDT = subSysStatus->getPreviousDT();  // Δt^n

  // BDF2 变步长系数
  const CFreal alpha = oldDT / newDT;              // α = Δt^n / Δt^{n+1}
  CFreal xi = 1. / (1.+ alpha);                    // ξ = 1/(1+α)
  CFreal theta = 1.;

  // 第一步退化为后向 Euler（没有 U^{n-1}）
  if (subSysStatus->getNbIter() == 1) { xi = 0.; theta = 1.0; }

  for (CFuint k = 0; !m_data->isAchieved(); ++k) {          // 子迭代（非线性/线性收敛）
    subSysStatus->setSubIter(k);
    getMethodData()->getCollaborator<SpaceMethod>()->prepareComputation();

    // Jacobian 冻结策略：k>1 后不再重算 Jacobian
    const bool jfnkMode = !m_data->getInitialDoComputeJacobFlag();
    if (jfnkMode) { m_data->setDoComputeJacobFlag(false); }
    else if (kStride == 0) {
      (m_data->freezeJacobian() && k > 1) ? m_data->setDoComputeJacobFlag(false)
                                         : m_data->setDoComputeJacobFlag(true);
    }
    getMethodData()->getCollaborator<SpaceMethod>()->setComputeJacobianFlag(...);

    getMethodData()->getCollaborator<SpaceMethod>()->computeSpaceResidual(theta);  // R(U^(k))

    if (m_data->getDoComputeJacobFlag() || jfnkMode) {
      getConvergenceMethodData()->getCFL()->update(cvgst.get());
    }
    // ... 求解线性系统、更新解 U ← U + ΔU
  }
}
```

| 代码 | 数学/算法含义 |
|------|---------------|
| `alpha = oldDT/newDT` | $\alpha=\Delta t^n/\Delta t^{n+1}$（变步长比） |
| `xi = 1/(1+alpha)` | BDF2 变步长系数（首步 $\xi=0$ 退化为后向 Euler） |
| `theta` | 传入 `computeSpaceResidual(theta)` 的残差因子，即 `getResFactor()`（4.2.3） |
| 子迭代循环 `k` | 内层 Newton/线性收敛，由 `Data.MaxSteps` 与 `Data.Norm` 控制 |
| `freezeJacobian` | 冻结 Jacobian：只算一次，后面复用（省时，但收敛变慢） |
| `jfnkMode` | JFNK（Jacobian-Free Newton–Krylov）：永不显式装配 Jacobian，用矩阵-向量积近似 |

**Crank–Nicolson**（二阶、时间中心）：$\dfrac{U^{n+1}-U^n}{\Delta t} = -\dfrac{1}{2V}\left[R(U^{n+1})+R(U^n)\right]$。对称、二阶精度，但对间断敏感（易振荡），故有 `CrankNicholsonLim`（限幅变体）。

**BDF2 与 CN 的"双时间步"**：非定常问题在每个物理时间步内做子迭代（内层收敛后再推进），由 `Data.MaxSteps`（最大子迭代数）+ `Data.Norm`（收敛判据）控制。

## 4.8 线性系统（LSS）：Jacobian 装配与求解

### 4.8.1 Jacobian 矩阵的结构

$J=\partial R/\partial U$ 是 $(N_{cells}N_{eq})\times(N_{cells}N_{eq})$ 的**分块稀疏矩阵**：

- 每个"块"是 $N_{eq}\times N_{eq}$（如 Euler 2D 是 $4\times4$）；
- **非零块**只出现在"有面相连的单元对"之间——即对单元 $i$，其行上的非零块对应 $i$ 自身与它的所有面邻居；
- 结构由网格**拓扑**决定，与解无关 → 可预先生成（稀疏模式）。

$$\begin{pmatrix}
\ddots & & & \\
& J_{ii} & J_{ij} & \\
& J_{ji} & J_{jj} & \\
& & & \ddots
\end{pmatrix},\qquad J_{ij} = \frac{\partial R_i}{\partial U_j}$$

### 4.8.2 数值 vs 解析 Jacobian

**数值（有限差分）Jacobian**：对每个未知量扰动一次，重算残差：

$$J_{ij}[e,c] \approx \frac{R_i[e](U_j[c]+h) - R_i[e](U_j[c])}{h},\qquad h = \epsilon\cdot\max(\lvert U_j[c]\rvert, \text{ref}[c])$$

**优点**：实现通用（不需要推导导数）；**缺点**：$N_{eq}$ 倍残差计算开销，且 $\epsilon$ 选取敏感。

**解析 Jacobian**：由 VarSet 提供 $\partial\mathbf F/\partial U$ 的解析表达式（变量集 `LinearVar = Roe` 等专门用于线化）。**优点**：精确、快；**缺点**：需要数学推导（NEQ 的物性库提供 `flagJac` 接口）。

**源码对照**（`plugins/FiniteVolume/FVMCC_ComputeRhsJacob.cxx:98-157`）：

```cpp

{
  computeNoAxiUpFactors();                                   // （非轴对称）系数
  _acc->setRowColIndex(0, _currFace->getState(0)->getLocalID());   // 行/列：左单元
  _acc->setRowColIndex(1, _currFace->getState(1)->getLocalID());   // 行/列：右单元

  for (CFuint iCell = 0; iCell < 2; ++iCell) {

    for (CFuint iVar = 0; iVar < nbEqs; ++iVar) {            // 逐个变量扰动

      _numericalJacob->restore(iVar, state[iVar]);           // 恢复 U[c]
    }
  }
  // _acc 提交到 LSS 矩阵的对应位置
}
```

```
2.  if 需要重算 Jacobian（非冻结、非 JFNK）:
3.      清空 LSS 矩阵

8.              F⁺ ← RiemannFlux(...)               # 重算通量

14. ΔU ← LSS.solve(A, b)                            # GMRES + ILU/ASM
15. U ← U + ΔU
```

## 4.9 残差分布法（RDS / FluctSplit）算法详解

### 4.9.1 数学推导

RDS 是**节点中心**方法：未知量存在网格节点上，在每个单元（三角形 2D / 四面体 3D）上计算残差，再分摊给顶点。

**第 1 步：单元残差（fluctuation）**

$$\phi^T = \oint_{\partial T}\mathbf F\cdot\mathbf n\,dS \approx \sum_{j\in T}K_j U_j$$

其中 $K_j$ 是**分布矩阵**（$N_{eq}\times N_{eq}$），对线性插值有 $K_j = \frac{1}{d}\mathbf A(\bar U)\cdot\mathbf n_j$（$\mathbf n_j$ 是节点 $j$ 所对面的内法向×面积，$d$ 为空间维数）。注意 $\sum_j K_j = 0$（对常状态，残差为零——**守恒性**）。

**第 2 步：特征分裂**

把 $K_j$ 按特征值正负分解：$K_j = K_j^+ + K_j^-$，其中

$$K_j^{\pm} = R\Lambda^{\pm}R^{-1},\qquad \Lambda^+ = \max(\Lambda,0),\ \Lambda^- = \min(\Lambda,0)$$

$K^+$ 对应"向节点 $j$ 方向传播的信息"（迎风方向）。

**第 3 步：分布（关键：各格式的差别就在这里）**

$$\phi_i = \beta_i\,\phi^T,\qquad \sum_i\beta_i = I\ (\text{守恒性})$$

| 格式 | 分布系数 $\beta_i$ | 特性 |
|------|-------------------|------|
| **N 格式** | $\beta_i^N = K_i^+\left(\sum_j K_j^+\right)^{-1}$ 但用"双侧"修正以确保正型 | 一阶、正型（单调、无过冲）、鲁棒，耗散较大 |
| **LDA 格式** | $\beta_i^{LDA} = K_i^+\left(\sum_j K_j^+\right)^{-1}$ | **二阶、线性、无耗散**（多维迎风），光滑区精度极高；间断附近可能振荡 |
| **LDA-PSI / Blended** | 在 N 与 LDA 间按"正型限制器"混合 | 兼顾精度与单调性（B 格式/PSI 限制器） |
| **SUPG** | 加流线迎风耗散 | 稳定化的 Galerkin |
| **FCT** | 通量校正输运 | 强间断（显式时间推进） |

> **为什么 LDA 是"多维迎风"？** 有限体积的迎风是"沿面法向"的一维迎风；RDS 的 $K_j^+$ 直接按单元内所有方向的特征波分解，因此是**真正多维**的迎风——这是 RDS 在非结构三角形网格上精度高、对网格方向不敏感的原因。

### 4.9.2 源码对照：`LDASchemeSys::distribute()`

**位置**：`plugins/FluctSplit/LDASchemeSys.cxx:67`

```cpp
void LDASchemeSys::distribute(vector<RealVector>& residual)
{
  const vector<State*>& tStates = *getMethodData().getDistributionData().tStates;  // 单元顶点状态

  // ① 计算总残差 φ^T = Σ K_j U_j
  _k = (*_kPlus[0]) + (*_kMin[0]);            // K_0 = K_0^+ + K_0^-
  _phi = _k * (*tStates[0]);                  // φ ← K_0 U_0
  _sumKplus = *_kPlus[0];                     // ΣK^+ ← K_0^+
  for (CFuint iState = 1; iState < _nbStatesInCell; ++iState) {
    _k = (*_kPlus[iState]) + (*_kMin[iState]);
    _phi += _k*(*tStates[iState]);            // φ += K_j U_j
    _sumKplus += *_kPlus[iState];             // ΣK^+ += K_j^+
  }

  // ② 求 (ΣK^+)^{-1}
  _inverter->invert(_sumKplus, _invK);
  _uTemp = _invK*_phi;                        // (ΣK^+)^{-1} φ^T

  // ③ 分布：φ_i = K_i^+ (ΣK^+)^{-1} φ^T
  for (CFuint iState = 0; iState < _nbStatesInCell; iState++) {
    residual[iState] = (*_kPlus[iState])*_uTemp;
    if (getMethodData().getDistributionData().computeBetas) {
      (*getMethodData().getDistributionData().currBetaMat)[iState] = (*_kPlus[iState])*_invK;  // β_i
    }
  }
}
```

**公式 ↔ 代码对照**：

| 数学 | 代码 |
|------|------|
| $K_j^+$ | `_kPlus[iState]` |
| $K_j^-$ | `_kMin[iState]` |
| $\phi^T=\sum_j K_jU_j$ | `_phi`（循环中累加 `_k*(*tStates[iState])`） |
| $\sum_j K_j^+$ | `_sumKplus` |
| $(\sum_j K_j^+)^{-1}$ | `_invK`（由 `_inverter->invert` 求得） |
| $\beta_i = K_i^+(\sum K^+)^{-1}$ | `currBetaMat[iState]` |
| $\phi_i = \beta_i\phi^T$ | `residual[iState]` |

**守恒性验证**：$\sum_i\beta_i = (\sum_i K_i^+)(\sum K^+)^{-1} = I$ ✓ ——这就是"每个单元贡献给各节点的残差之和 = 单元总残差"，保证全局守恒。

### 4.9.3 RDS 算法伪代码

```
算法：一步 RDS 残差计算（显式）
1.  for 每个单元 T（三角形/四面体）:
2.      计算节点状态 U_j（j = 1..d+1）
3.      for 每个节点 j:
4.          K_j ← (1/d)·A(Ū)·n_j            # 分布矩阵（n_j：节点对面内法向×面积）
5.          (K_j^+, K_j^-) ← 特征值正负分解
6.      φ^T ← Σ_j K_j U_j                    # 单元总残差
7.      switch 分布方案:
8.          LDA:  β_j ← K_j^+ (ΣK^+)^{-1}
9.          N:    β_j ← （正型修正后的 N 分布）
10.         Blended: β_j ← ψ·β^LDA + (1-ψ)·β^N（ψ 由正型限制器定）
11.     for 每个节点 j:  R_j ← R_j + β_j φ^T   # 累加到全局节点残差
12. 更新：U_j^{n+1} = U_j^n - (Δt/V_j) R_j     # V_j：节点的中对偶（median-dual）体积
```

**注**：RDS 的节点控制体是**中对偶单元**（median-dual cell）——由连接单元重心与边中点的线段围成。这与 FVM 的"单元即控制体"不同，是节点中心方法的特点。

### 4.9.4 RDS 配置要点

| 项目 | 说明 |
|------|------|
| 插件 | `FluctSplit`（920 文件，含子库 `libFluctSplitScalar/libFluctSplitSystem/libFluctSplitNavierStokes`）+ `FluctSplitNEQ` |

## 4.10 通量重构（FR / CPR）高阶算法

### 4.10.1 数学推导

FR 的核心：**在单元内用多项式表示解和通量，用修正函数处理单元间断面的通量不连续**。

**第 1 步：解点与通量点**

单元（参考坐标 $\xi\in[-1,1]$）内布置：

- $P+1$ 个**解点**（solution points）：存放未知量 $U$（Gauss–Legendre 点等）；
- $P+2$ 个**通量点**（flux points）：包含两个边界点 $\xi=\pm1$，用于计算界面通量。

由解点值插值得 $P$ 阶多项式 $U_h(\xi)$，进而得到通量多项式的插值 $\tilde{\mathbf F}(\xi)$（注意：一般 $\tilde{\mathbf F}$ 只是 $P$ 阶，而真实的 $\mathbf F(U_h)$ 是更高阶，这里有投影误差）。

**第 2 步：修正函数（correction function）**

界面处的公共通量（common flux）$\hat F_L,\hat F_R$ 由 Riemann 求解器给出（4.4）。它与内部插值通量在边界的差，用修正函数 $g_L,g_R$ 传播回单元内部：

$$\hat{\mathbf F}(\xi) = \tilde{\mathbf F}(\xi) + \underbrace{\left[\hat F_L - \tilde F(-1)\right]g_L(\xi)}_{\text{左界面修正}} + \underbrace{\left[\hat F_R - \tilde F(1)\right]g_R(\xi)}_{\text{右界面修正}}$$

修正函数要求：$g_L(-1)=1,\ g_L(1)=0$（右反之），且 $g$ 为 $P+1$ 阶多项式。

**第 3 步：残差**

$$\frac{dU_h}{dt} = -\frac{\partial \hat{\mathbf F}}{\partial \xi}\bigg|_{\text{各解点}}$$

**VCJH 族的妙处**：修正函数族由单参数 $c$ 控制，**$c$ 取不同值可恢复不同经典格式**：

| $c$ 值 | 恢复的格式 |
|--------|-----------|
| $c=0$ | DG（间断伽辽金） |
| $c=c_{SD}$ | SD（谱差分） |
| $c=c_{HU}$ | Huynh 格式（$g_{DG}$ 的另一种） |
| 其他 | 连续谱上的能量稳定格式 |

CFcase 中 `Data.CorrectionFunctionComputer = VCJH` + `Data.VCJH.CFactor = 9.5e-4` 即在此谱上取值。**$c$ 越大耗散越大**（能量稳定性与精度的权衡）。

### 4.10.2 源码对照：`FluxReconstructionSolver::computeSpaceResidualImpl()`

**位置**：`plugins/FluxReconstructionMethod/FluxReconstructionSolver.cxx:466`

```cpp

{
  const bool linearMode = m_data->isLinearResidualMode();

  if (!linearMode) { m_preprocess->execute(); }   // ① 前处理（更新插值矩阵等）
  m_data->setResFactor(factor);                   // ② 设置残差因子（时间推进传来的 θ）

  if (!linearMode) { m_physicality->execute(); }  // ④ 物理性强制（密度/压力为正）
  applyBC();                                      // ⑤ 施加边界条件（虚拟态）
  m_convSolve->execute();                         // ⑥ 对流项求解（核心）
  if (m_artificialViscStr != "Null") { m_artificialVisc->execute(); }  // ⑦ 人工粘性
  if (m_data->hasDiffTerm()) {                    // ⑧ 扩散项
    m_diffSolve->execute();
    applyBCDiffImpl();                            //    扩散边界通量
  }
  addSourceTermsImpl();                           // ⑨ 源项
  if (!linearMode) { m_computeError->execute(); }
  if (m_data->isResidualTransformationNeeded()) { m_finalizeRHS->execute(); }
}
```

| 步骤 | 数学/算法含义 | 对应 4.10.1 |

| ① `m_preprocess` | 更新解点/通量点的插值、微分矩阵 | 第 1 步 |

### 4.10.3 FR 算法伪代码

```
算法：FR 空间残差（每个单元）
1.  U_h ← 解点值插值成 P 阶多项式
2.  在通量点计算 F̃ = F(U_h)
3.  把 F̃ 插值为 P 阶通量多项式
4.  for 每个界面（左/右）:
5.      (U^-, U^+) ← 本单元/邻单元在界面的外推值
6.      F̂ ← RiemannFlux(U^-, U^+, n)              # 公共通量（4.4）
7.      δ_L ← F̂_L - F̃(-1);   δ_R ← F̂_R - F̃(+1)   # 界面通量跳跃
8.  F̂(ξ) ← F̃(ξ) + δ_L·g_L(ξ) + δ_R·g_R(ξ)         # 修正函数传播（VCJH 参数 c）
9.  R ← -∂F̂/∂ξ （在各解点上）                       # 通量散度
10. if 有粘性: R ← R - ∂F̂_v/∂ξ（BR2/IP/LocalApproach）
11. return R
```

> ⚠️ **旧版手册此处有误**：曾写作 `Data.FaceDiffFlux = NSStdBR2`。代码树中**不存在** `NSStdBR2`；`NSStd*` 是 `FaceTermComputer` / `BndFaceTermComputer` / `VolTermComputer` 族的前缀，而 `FaceDiffFlux` 的取值是 `NSBR2Approach` 一类的 `*Approach` 名字。二者属于**不同选项、不同命名空间**，请勿混用。

**项计算器三件套**：`VolTermComputer / FaceTermComputer / BndFaceTermComputer`——分别计算体积项、内部面项、边界面项，与 FR 的 `m_convSolve`/`m_diffSolve` 角色对应。`NSStd*`（标准）与 `NSCompact*`（紧致）的区别在于通量计算是否复用插值矩阵；`NSQuadFree*`（无求积）用 nodal 直接求积以省去求积点插值。

### 4.11.2 粘性（扩散）项的三条路线

高阶方法处理粘性项的难点：解在单元间断断，**梯度无定义**。三条路线：

| 路线 | 全称 | 思想 | 特点 |
|------|------|------|------|
| **BR2** | Bassi–Rebay 2 | 引入"辅助变量" $\Theta=\nabla U$，两次求解 | 紧凑模板、稳定，SD 常用 |
| **IP** | Interior Penalty | 在弱形式中加跳项惩罚 $\sigma_e[h^{-1}][U][\varphi]$ | 经典 DG 粘性处理，需调惩罚系数 |
| **LocalApproach** | 局部法 | 在界面局部构造连续的多项式再求梯度 | 精度高，但**模板宽**（需 `CellCenteredDiffLocalApproachSparsity`，4.8.3） |

配置：`Data.FaceDiffFlux = *BR2 | *IP | *LocalApproach`（算例名中常显式标注，便于横向对比）。

### 4.11.3 谱体积（SV）

**插件**：`SpectralFV` + `SpectralFVNavierStokes`。把单元划分为若干**子单元（谱体积）**，在每个子单元上做有限体积更新。**兼具 DG 的紧凑模板与 FVM 的守恒性**；配置风格与 SD 一致（`accpulse2d-sfvm*.CFcase` 族）。

### 4.11.4 间断伽辽金（DG）

**插件**：`DiscontGalerkin`（51 文件）。标准弱形式 + 数值通量 + 跳项惩罚（4.11.2 的 IP 路线），含局部投影限制器。物理覆盖相对 FR/SD 较窄，高阶研究推荐 FR 路线。

### 4.11.5 有限元（FE）

**插件**：`FiniteElement`（165 文件）。连续 Galerkin 弱形式 + 单元矩阵装配，服务 `StructMech`、`Heat` 等固体/输运问题（3.4 节）。与 FVM 的关键差别：解在节点上连续、用基函数加权积分（而非控制体守恒）。

## 4.14 动网格技术（ALE）

### 4.14.1 数学：为什么要改方程

网格运动时，控制体随时间变化，雷诺输运定理给出：

$$\frac{d}{dt}\int_{\Omega(t)}U\,dV = \int_{\Omega(t)}\frac{\partial U}{\partial t}dV + \oint_{\partial\Omega(t)}U\,(\mathbf u_g\cdot\mathbf n)\,dS$$

其中 $\mathbf u_g$ 是**网格速度**。于是守恒律变为（ALE 形式）：

$$\frac{d}{dt}\int_{\Omega(t)}U\,dV + \oint_{\partial\Omega(t)}\left[\mathbf F - U\mathbf u_g\right]\cdot\mathbf n\,dS = \ldots$$

**关键变化**：通量中出现"网格运动携带的输运" $-U\mathbf u_g$。**数值格式必须相应修改**——这就是 `*ALE` 变体通量格式（`RoeALE`、`AUSMPlus2DALE`、`AUSMPlusUp2DALE`）存在的理由。

### 4.14.2 几何守恒律（GCL）

**GCL 要求**：即使流场是均匀的（常值解），运动网格上的格式也必须**精确保持**这个常值解。数学表达：

$$\frac{d}{dt}\int_{\Omega(t)}dV = \oint_{\partial\Omega(t)}\mathbf u_g\cdot\mathbf n\,dS$$

即"控制体体积变化率 = 网格运动扫过的体积"。**违反 GCL 会在动网格上产生非物理的质量/能量源**，是动网格计算最常见的错误来源。COOLFluiD 由 ALE 通量格式与网格速度接口共同保证 GCL。

### 4.14.3 接入方式

1. **方法钩子**：SpaceMethod 的 `BeforeMeshUpdateCom / AfterMeshUpdateCom` 选项（`CellCenterFVM.cxx` 定义）在每步网格更新前后插入命令；
2. **通量格式切 ALE 变体**：`RoeALE`、`AUSMPlus2DALE`、`AUSMPlusUp2DALE` 等（4.4.7）；
3. **FSI 联动**：与耦合器配合（`SubSystemCoupler/testcases/FSI/twoCoupledNonMatchingSubSystems_Moving.CFcase` 等），运动由耦合面数据驱动。

**网格变形算法**（`MeshRigidMove` 等插件）：

| 运动类型 | 命令/类 |
|----------|---------|
| 刚体/指定运动 | `Piston`、`PistonConstantSpeed`、`OscillatingAirfoil`（Prepare 命令） |
| Laplacian 光顺 | `MeshLaplacianSmoothing`（求解 $\nabla^2\mathbf x=0$，边界位移向内传播） |
| 弹簧类比 | `MeshAdapterSpringAnalogy`（把每条边看作弹簧） |
| 有限元变形 | `MeshFEMMove`（`FEMMove`，把网格当弹性体求解） |

## 4.15 耦合求解策略

### 4.15.1 子系统耦合（SubSystemCoupler）

- **机制**：一个 CFcase 声明多个 SubSystem（`Simulator.SubSystems/SubSystemTypes`），可按 `SubSystemRanks` 分区；`SubSystemCoupler` 插件（206 文件）在界面 TRS 间做**守恒插值与数据交换**（支持非匹配网格：`twoCoupledNonMatchingSubSystems*.CFcase`）；
- **数学要求**：界面上必须满足**通量守恒与状态连续**：

  $$q^{fluid} = q^{solid}\ \text{（热流连续）},\qquad T^{fluid} = T^{solid}\ \text{（温度连续）}$$

  非匹配网格上用插值（如径向基函数、面积加权）保证积分量守恒；
- **典型应用**：共轭传热（CHT：流体侧 `CoupledNoSlipWall*` BC ↔ 固体侧 `Heat` 模型）、FSI；
- 耦合迭代由 Maestro 编排、停止条件控制（第 2.3.1 节）。

### 4.15.2 并发耦合（ConcurrentCoupler）

子系统间**同步推进**（同一物理时刻并行交换），适合强耦合（FSI 运动壁、电磁-流动）场景；配置模式与 4.15.1 一致。

### 4.15.3 流场—辐射耦合

`RadiativeTransfer` 插件（DOM/MonteCarlo 求解器 + HSNB/PARADE/Grey 谱带）以命令形式嵌入 NEQ 求解循环：

```
流场 (T, T_v, y_i)  →  辐射体计算谱吸收/发射  →  净辐射源项 omegRad  →  回写 NEQ 能量方程
```

数学上即能量方程右端增加 $-\nabla\cdot\mathbf q_{rad}$（3.2.7）。开关与输出命令（`RadiativeTransferOutputFVMCC`）见第 6.2.5 节；Fire II 类对标算例见第 7.3.3 节。

### 4.15.4 流—固—热三场耦合工作流

典型链路：`NavierStokes(NEQ)`（流）↔ `Heat`（壁内导热，`CoupledNoSlipWall*` 壁面温度/热流交换）↔ `StructMech`（热应变，`StructMechHeat`）。三子系统在 `Maestro` 下以 `SubSystemCoupler` 串接，逐场迭代至界面量收敛。

## 4.16 GPU 加速实现细节

- **算子层**：`FiniteVolumeCUDA`（FVMCC RHS/Jacobian 核函数）、`FluxReconstructionCUDA`（FR 算子），编译需 `CF_ENABLE_CUDA`；显存分配方式受 `CF_CUDA_MALLOC` 控制；设备经内核 `CudaDeviceManager` 选择并可由 CFcase 配置；
- **求解器层**：`PARALUTION`（GPU 迭代后端）与 ViennaCL 路径（`CF_ENABLE_VIENNACL`）；
- **数据管理**：数据搬运按套接字（DataSocket）粒度进行，`CudaTimer` 提供核计时；
- **调优建议**：1) 先用 `--testEnv` 与小算例验证 GPU 链路；2) 对比 `CudaTimer` 与 CPU 耗时定位传输瓶颈；3) GPU 路径的物理覆盖有限（Euler/FVM、FR 算子），非平衡/MHD 生产计算仍以 MPI 为主；4) 集群上 GPU 任务脚本模板见第 9.6 节。

## 4.19 精度、稳定性、收敛性与复杂度

前 18 节回答"算法是什么、怎么实现"；本节回答工程上同样重要的四个问题：**算得准不准（精度）、会不会炸（稳定性）、能不能收敛（收敛性）、要花多少资源（复杂度）**。

### 4.19.1 精度阶与截断误差

**空间精度**（$d$ 为维数，$P$ 为多项式阶）：

| 方法 | 重构/近似 | 形式精度阶（光滑解） | 间断附近 |
|------|-----------|---------------------|----------|
| FVM 一阶（`Constant` 重构） | 分片常数 | $O(\Delta x)$ | 一阶 |
| FVM 二阶（`LinearLS*` + 限制器） | 分片线性 | $O(\Delta x^2)$ | **降为一阶**（限制器在极值/间断处 $\phi\to0$） |
| RDS（LDA） | 节点线性插值 | $O(\Delta x^2)$ | 需 PSI/B 型限制保正型 |
| FR / SD / DG（$P$ 阶） | $P$ 阶多项式，自由度 $(P+1)^d$ | $O(\Delta x^{P+1})$ | 降为一阶（需人工粘性/限制） |

**为什么间断附近必然降阶？** 由 **Godunov 定理**：任何高于一阶的**线性**单调格式不存在；因此高阶格式必须用**非线性**限制器，而限制器在间断处自动退化为一阶——这是数学上的必然，不是实现的缺陷。**实践含义**：激波分辨率由"一阶区"的单元数决定，因此激波网格加密的收益低于光滑区。

**时间精度**：

| 格式 | 阶 | 备注 |
|------|-----|------|
| 前向 Euler / 后向 Euler | $O(\Delta t)$ | 一阶；后向 Euler 常用于定常求解（时间精度无意义） |
| Crank–Nicolson、BDF2 | $O(\Delta t^2)$ | 二阶；BDF2 首步退化为后向 Euler（4.7.5） |
| RK2 / RK3 / RK4 | 2 / 3 / 4 阶 | 显式，受 CFL 限制 |

**总误差** = 空间截断误差 + 时间截断误差 + 迭代残差 + 舍入误差。**最常见的误判**：残差降到 $10^{-6}$ 不等于解精确到 $10^{-6}$——残差是**迭代收敛**的度量，不是**离散误差**的度量。要评估真实精度必须做**网格/阶次收敛研究**（同一算例在 3 套网格或 3 个多项式阶上求解，用 Richardson 外推估计收敛阶与离散误差）。

### 4.19.2 稳定性

**(1) 显式格式：CFL 条件**

$$\Delta t \le \mathrm{CFL}\cdot\min_i\frac{V_i}{\sum_f\lambda_{max}A_f},\qquad \lambda_{max}=\lvert u_n\rvert+a$$

含粘性时还需满足抛物型条件 $\Delta t\lesssim \dfrac{V}{\nu A^2/V}\sim\dfrac{\Delta x^2}{\nu}$（4.5.3），**边界层网格极薄时该条件比对流条件严苛得多**——这是显式方法在粘性高 $Re$ 问题上不实用的原因。

**(2) 隐式格式**：线性层面**无条件稳定**（后向 Euler / BDF2 的绝对稳定域含整个左半平面），因此可取 $\mathrm{CFL}\gg1$。**但稳定性 ≠ 收敛性**：隐式仍有

- **Newton 收敛半径**问题：初值太差时线化失效 → 需 CFL 爬升（4.7.4）或网格序列初始化；
- **Jacobian 冻结**引入的"隐式误差"（4.12）：过度冻结会使收敛变慢甚至停滞；
- **非精确 Newton**：内层 Krylov 容差太松（如 $10^{-1}$）会破坏外层二次收敛。

**(3) 物理/数值正定性**：密度、压力、温度必须为正。高阶方法尤其易出负密度（多项式过冲），故 FR 有 `m_physicality` 强制（4.10.4）；FVM 靠限制器（4.3.3）与正型通量（HLL 系）保证。

**(4) 熵条件**：数值解必须排除膨胀激波，靠熵修正与格式耗散（3.3.5、4.4.4）；carbuncle 是强激波下的另一类失稳，需专用修复（`RoeSA`）。

### 4.19.3 收敛性

**判据**（CFcase `StopCondition`）：残差范数（$\|R\|_1,\|R\|_2,\|R\|_\infty$）降到阈值，或迭代数上限，或物理量（如气动系数）稳定。

**收敛行为的三个阶段**（定常问题典型）：

1. **启动期**：残差震荡/缓慢下降，宜小 CFL（1–5）+ 一阶或低耗散格式；
2. **快速下降期**：残差指数下降，宜爬 CFL（4.7.4）、开二阶；
3. **平台期**：残差停滞在某个水平不再下降——常见原因：限制器在极值点反复开关（Barth 系尤其明显）、Jacobian 冻结过久、非匹配界面/周期边界的守恒残差、源项与通量不平衡。

**非精确 Newton 的收敛**：外层 Newton 理论上是**二次收敛**（误差平方递减），前提是内层线性求解足够精确（相对容差 $\lesssim10^{-2}$–$10^{-4}$）且 Jacobian 足够新鲜。若观察到"线性收敛"（误差每次乘常数），通常说明 Jacobian 被冻结过久或 Krylov 容差过松。

**残差停滞/发散的系统排查**见第 12.5 节。

### 4.19.4 复杂度与资源估算

设 $N_c$：单元数，$N_f$：面数（$\approx\frac{d+1}{2}N_c$），$N_e$：每单元方程数（Euler 2D = 4，NS+SA = 5，$k$-$\omega$ = 6，NEQ 可达 10+），$P$：多项式阶。

**单次残差计算**：

| 环节 | 复杂度 | 说明 |
|------|--------|------|
| 重构（梯度） | $O(N_c\,N_e\,n_{stencil})$ | $n_{stencil}$ 为模板单元数 |
| 界面通量（Roe 类） | $O(N_f\,N_e^3)$ | 主导项是特征分解/矩阵乘法（$N_e\times N_e$） |
| 界面通量（中心/AUSM 类） | $O(N_f\,N_e)$ | 无特征分解，更便宜 |
| 粘性通量 | $O(N_f\,N_e)$（另加梯度 $O(N_c N_e)$） | 需面控制体梯度 |

**时间推进**：

| 类型 | 每步复杂度 | 内存 |
|------|-----------|------|
| 显式（RK） | $O(N_f N_e^{\,2\sim3})$ × 级数 | $O(N_c N_e)$（仅存解与残差） |
| 隐式（数值 Jacobian 装配） | 装配 $O(N_f\,N_e\cdot N_e^{\,2\sim3})$：**需对每个变量重算通量，再乘 $N_e$** ≈ $O(N_f N_e^{\,3\sim4})$ | Jacobian: $O(N_c\,n_{nb}\,N_e^2)$（$n_{nb}$：邻居数，2D 三角形≈4，3D 四面体≈5） |
| 隐式（解析 Jacobian） | 装配 $O(N_f N_e^{\,2\sim3})$（省去 $N_e$ 倍重算） | 同上 |
| 线性求解（GMRES+ILU） | 每次 Krylov 迭代 $O(nnz)$；ILU 分解 $O(N^{1.2\sim1.5})$ | 与 Jacobian 同量级 |
| LU-SGS | $O(N_c N_e^2)$，无矩阵存储 | **$O(N_c N_e)$**，内存友好 |

**高阶方法的自由度增长**：FR/SD/DG 的自由度 $\approx N_c(P+1)^d$，且时间步受 $\Delta t\propto 1/P^2$（CFL 与阶次相关）限制 → **总代价大致随 $P^{d+2}$ 增长**。这是高阶方法在 3D 工程问题上昂贵的原因，也是"网格序列/阶次延续（低阶解升阶）"策略（4.12）的价值所在。

**并行**：MPI 分区后每步通信量 $\propto$ 分区界面面积（ghost 单元数），计算量 $\propto N_c/P_{ranks}$；因此**并行效率随"面体比"上升而下降**——小网格用多核会得不偿失（经验：每 rank 至少保留数万单元）。

> **内存估算实例**（3D Euler，$N_c=10^6$，$N_e=5$，$n_{nb}=5$，双精度 8 B）：Jacobian 非零块 $\approx 10^6\times6\times5^2\times8\,\mathrm{B}\approx1.2\,\mathrm{GB}$；加上 PETSc 的 Krylov 工作向量与 ILU 填充（通常 2–3 倍），隐式求解 100 万单元 3D 问题常需 **4–8 GB/rank 量级**的内存规划。若内存不足，优先改用 LU-SGS 或矩阵-free（JFNK）。
