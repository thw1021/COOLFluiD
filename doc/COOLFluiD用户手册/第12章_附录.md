## 12.1 报错阅读指南

### 12.1.1 异常输出格式（实测）

任何 `Common::Exception` 派生类抛出时的标准输出（默认 `ExceptionOutputs=true`）：

```
+++ Exception thrown +++++++++++++++++
From : 'File: 'src/Framework/...' Line: N'
Type : 'NoSuchValueException'
Message :
In factory of [SpaceMethod] a provider with the name [Foo] was not found while trying to get the provider
++++++++++++++++++++++++++++++++++++++
+++ Exception backtrace ++++++++++++++
<调用栈（地址/符号）>
++++++++++++++++++++++++++++++++++++++
```

- **From**：抛出位置（文件+行号）——从这里开始看，通常是问题发生处；
- **Type**：异常类名（下表）——决定处置方向；
- **Message**：具体原因（Provider 名、文件名、键名……）；
- **backtrace**：默认开启（`ExceptionDumps=true`），符号化程度取决于编译选项。

### 12.1.2 运行期开关（实测 `CFEnv.cxx` 键，写 `Simulator.CFEnv.…` 或直接 `CFEnv.…`）

| 键 | 默认 | 作用 |
|----|------|------|
| `DoAssertions` | true | 动态开关 `cf_assert`（关掉可绕过崩溃继续跑） |
| `AssertionDumps` | true | 断言失败时打印 backtrace |
| `AssertionThrows` | false | 断言失败抛异常而非 `abort()`（便于批量捕获） |
| `ExceptionOutputs` | true | 是否打印异常文本 |
| `ExceptionDumps` | true | 是否打印异常 backtrace |
| `ExceptionAborts` | false | 异常时立即 `abort()`（便于抓 core） |
| `ExceptionLogLevel` | - | 异常对应日志级别 |
| `RegistSignalHandlers` | false | 注册 CPU 信号处理器（FPE/段错误） |
| `OnlyCPU0Writes` | true | 仅 0 号进程写 stdout |
| `TraceToStdOut` | false | 追踪信息同时输出到 stdout |
| `TraceActive` | false | 开关 `CFAUTOTRACE` 追踪 |
| `VerboseEvents` | false | 事件（signal 收发）详细输出 |
| `ErrorOnUnusedConfig` | false | 未消费的配置键由警告升级为异常 |
| `MainLoggerFileName` | "output.log" | 主日志文件名 |

### 12.1.3 典型症状 → 处置速查

| 症状关键词 | 异常类 | 处置（详见节） |
|-----------|--------|----------------|
| `a provider with the name … was not found` | `NoSuchValueException` | 12.3 |
| `Unused User Configuration Arguments` | 警告→`ConfigOptionException` | 12.3 |
| `ParserException` / 行号列号 | `ParserException` | 12.3 |
| `not a valid CFmesh` / 版本 | `BadFormatException`、`FileFormatException` | 12.4 |
| `File … could not be opened` | `FilesystemException` | 12.4 |
| `Assertion failed` | `FailedAssertionException`（或 abort） | 12.7 |
| 残差 `nan` / `inf` | 数值问题（无异常） | 12.5 |
| `MPI_` 相关 / 卡死 | 并行问题（无异常） | 12.6 |
| `Floating point exception` 信号 | `FloatingPointException` | 12.7 |

## 12.2 编译与构建问题（关联第 8 章）

| 现象 | 原因与处置 |
|------|-----------|
| cmake 找不到依赖 | 用 `tools/scripts/install-coolfluid-deps.pl` / `install.sh` 装依赖；核对 `tools/conf/*.conf` 中的编译器/MPI/库路径 |
| 编译 OOM 中断 | 降低 `make -j` 并发；插件单独编译（`cmake --build . --target FiniteVolume`） |
| `libFoo.so: undefined reference` | 依赖库顺序：`LIST(APPEND Foo_cflibs …)` 必须声明；或该库未编译（`CF_BUILD_Foo=OFF`） |
| 单可执行模式报重复符号 | `CF_HAVE_SINGLE_EXEC` 下所有插件并入一个库，不能重复注册同名 Provider（12.3） |
| `CF_WARN_ORPHAN_FILES` 告警 | 源码目录有文件未列入 CMakeLists 清单；新增文件务必补进 `Xxx_files` |
| `CF_BUILD_Xxx_API` 未开导致头文件缺失 | 插件头文件默认不发布（第 11.6.10 节）；对外暴露接口的插件需显式置 ON |
| 修改源码后未生效 | 增量编译目标库；运行用 `--ldir` 指向 `build/dso` 下的最新 `.so` |

## 12.3 启动与配置问题（关联第 9 章）

### 12.3.1 Provider 未注册（最高频）

```
Type : 'NoSuchValueException'
In factory of [SpaceMethod] a provider with the name [Xxx] was not found…
```

排查顺序（实测链路，第 11.6.1 节）：
1. **插件是否加载**：`Simulator.Modules.Libs` 是否含插件库名；漏加载 → 库内全部 Provider 不存在；
2. **拼写**：注册名与 CFcase 键完全一致（大小写敏感）；`XxxMethod` vs 注册名 `XxxMethod`（`getModuleName()` 无关）；
3. **编译**：新增 Provider 的 `.cxx` 是否在 CMakeLists 清单中（第 11.6.6 节）；
4. 单可执行模式：Provider 是否被链接器丢弃（静态对象无引用——需保留符号）。

### 12.3.2 未消费的配置键

```
WARNING : Unused User Configuration Arguments:
Simulator.SubSystem.CellCenterFVM.Wall.m_param = 0.25
```

- 含义：该键没有任何对象消费——**键拼错、前缀路径写错、或对象未创建**（对象都不存在则无从消费）；
- 默认仅警告；`Simulator.CFEnv.ErrorOnUnusedConfig = true` 时升级为 `ConfigOptionException`（实测 `Simulator.cxx:290`），适合 CI 回归；
- 处置：对照对象真实前缀（`Simulator.SubSystem.<方法名>.<组名>.<键>`，第 9.2.2、9.3.1 节）逐一核对；疑似拼错时先用 `--testEnv`（第 9.5.1 节）过一遍。

### 12.3.3 CFcase 语法错误

`ParserException` 附行列号：`Syntax error at line N col M`。常见原因：括号不配对、字符串未加引号、`=` 写成了 `==`、注释 `#` 顶格放错位置。用 `--testEnv` 或先跑 `burgersFVM` 模板对照。

### 12.3.4 日志看不到内容

- 级别：`--log=700`（DEBUG_MIN，第 9.5.1 节）；`CFLog(WARN,…)` 级以下默认不显示；
- `MainLoggerFileName`：默认写 `output.log`（实测默认值）；
- 多进程：`OnlyCPU0Writes=true` 只留 0 号进程输出；并行 I/O 写文件数由 `NbWriters` 控制。

## 12.4 网格与几何问题（关联第 3、5 章）

| 现象 | 原因与处置 |
|------|-----------|
| `BadFormatException: … not a valid CFmesh` | 文件损坏或版本不符；确认 `.CFmesh` 头（`!COOLFLUID_VERSION` / `!CFMESH_FORMAT_VERSION` 及版本号）与读入器匹配（段结构与版本约定见第 9.4.1 节） |
| `FilesystemException` | 路径不存在/无权限；相对路径基准是运行目录；检查 `--scase` 与网格相对位置 |
| 命令 `usesTRS()` 但 `applyTRS` 的名字在网格中不存在 | 用 `--testEnv` 列 TRS 名（启动日志打印各 TRS，见 9.5.4）；CFcase 中 TRS 名与 `.CFmesh` 内一致（大小写敏感） |
| 几何形状/阶不匹配 | `CFPolyOrder`/`CFGeoShape` 声明与网格不符（2D/3D 混淆、线元/面元混淆） |
| 高阶法向/单元计算报错 | 高 PolyOrder 网格需对应 `ComputeFaceNormalsXxxP<n>` 系列命令（第 7.3 Cylinder 族） |

## 12.5 数值发散与不收敛（关联第 9 章）

排查路线（按概率排序）：

1. **初始化**：`InitComds`/`InitState` 是否把所有状态（含 ghost/远场）赋值；初值单位/参考量级错误是 NaN 的首要来源；
2. **BC 组合**：`BcComds`/`BcNames`/`applyTRS` 是否覆盖全部边界 TRS——遗漏的面默认无 BC（可能保持初值或垃圾值）；
3. **CFL 与时间步**：`CFL.Value`/`CFL.MaxValue` 过大（显式起步建议 ≤0.5）；`ComputeDT` 是否启用；瞬态用 `UnsteadySubSystem` 的 `TimeStep`；
4. **限制器/重构**：高阶重构（MUSCL/WENO）在间断附近需限制器；先降 P0/一阶验证稳定性；
5. **隐式加速**：LU-SGS/ILU 迭代次数（`NbSubIterations` 类键）过少或过多导致刚性振荡；
6. **物性**：温度范围触发负压强/负温度（热力学不变量越界），检查 `InitState` 与气体模型匹配；
7. **回归基准**：先用同网格的参考算例（第 7 章档案）确认环境正确，再改自己的参数；
8. 怀疑代码问题：`DoAssertions=true` + 最小网格复现，拿到 `FailedAssertionException` 的位置信息再决定是否上报。

> 通用技巧：把算例缩到最小（1 个区域、粗网格、10 步），`--log=700`（DEBUG_MIN）看每一步残差；NaN 首现步数可通过 `### Residual` 历史（第 7 章各档案头元数据）定位。

## 12.6 并行问题（关联第 2.5 节并行框架、第 9.5 节并行运行）

| 现象 | 处置 |
|------|------|
| `mpirun -np N` 但进程数/分区不一致 | ⚠️ **`coolfluid-solver` 无 `--mpi` 命令行选项**（实测 `apps/Solver/coolfluid-solver.cxx` 的 11 个参数中不含它，全库也无处理代码）；MPI 实现由编译期 MPI 库决定。进程数变化需重新分区/分块（第 9.5.2 节自动剖分）；保持各 `mpirun -np` 与网格剖分一致 |
| 找不到 `libmpi` | `LD_LIBRARY_PATH` 含 MPI 库路径；`tools/conf` 中 MPI 变量正确 |
| 输出交错混乱 | `OnlyCPU0Writes=true`；写文件进程数 `CFEnv.NbWriters`（并行 I/O） |
| 卡死/不同步 | 各进程 CFcase 不一致（共享文件系统缓存）；`SyncAlgo` 尝试 `Bcast`/`AllToAll`（实测键，默认 `Old`）；检查是否有进程静默失败（`ErrorOnUnusedConfig=true` + `ExceptionAborts=true` 提前暴露） |
| 批跑脚本模板 | 参考 `tools/scripts/run.sh`：`mpirun -np 8 ./coolfluid-solver --scase X >& X.txt` |

## 12.7 运行时与数据问题

| 现象 | 处置 |
|------|------|
| `Floating point exception`（SIGFPE） | `RegistSignalHandlers` 捕获并转成 `FloatingPointException`；先按 12.5 查数值根源 |
| 段错误（SIGSEGV） | `AssertionDumps/ExceptionDumps` 抓 backtrace；用 `--ldir` 对最新库重跑；最小化网格复现 |
| 内存不足 | 3D 高阶/DG 大模板（第 4.10 节高阶方法）内存按单元数×状态数×自由度估算；减小网格或降阶 |
| 输出写不进 | 检查输出目录权限与 `NbWriters` 匹配；`FilesystemException` 会给出文件名 |
| 结果与参考不一致 | 核对单位制、`CFEnv` 开关差异（如 `ErrorOnUnusedConfig`）、插件版本；用第 7 章同档案同版本复跑基准 |

## 12.8 调试技巧汇总

1. **`--testEnv`**（第 9.5.1 节）：不运行主循环，检查配置与网格，定位 90% 的配置类错误；
2. **日志分级**：`--log=INFO→DEBUG→TRACE` 逐级放大；`TraceActive=true` 开启 `CFAUTOTRACE` 函数进出追踪；
3. **未用键哨兵**：`ErrorOnUnusedConfig=true` 把拼写错误变成异常；
4. **异常即时报**：`ExceptionAborts=true` 拿到 core 文件（gdb 分析）；
5. **断言兜底**：`DoAssertions` 保持 true 运行测试算例，回归期定位越界/空指针；
6. **增量迭代**：改代码 → `cmake --build` 单插件 → `--ldir build/dso` 直跑，秒级反馈（第 11.1.1、11.8.1 节）；
7. **二分复现**：从 `burgersFVM` 起步逐项加功能，每步记录 `### Residual` 与输出差异。

### 12.12.2 数值方法与物理模型的经典文献（建议延伸阅读）

- **使用与再分发**：可自由使用、修改、再分发 COOLFluiD 本身；分发修改后的**库文件**时须遵循 LGPL（提供源码或可重新链接的目标文件）；
