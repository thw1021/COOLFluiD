# 第 1 章 项目概述与背景

本章回答三个问题：COOLFluiD 是什么（1.1）、它从何而来（1.2）、它擅长什么以及与其他求解器相比处于什么位置（1.3–1.5）。读完本章，你应当能够判断 COOLFluiD 是否适合你的问题，并知道后续章节应重点阅读哪些部分。

---

## 1.1 COOLFluiD 是什么

### 1.1.1 定位

COOLFluiD 是一个**面向 CFD（计算流体力学）与多物理场仿真的面向对象 HPC（高性能计算）平台**。它并不是一个"单一功能的求解器"，而是一个**可组合的仿真框架**：

- **物理层面**，覆盖可压缩流动（Euler/NS/RANS）、高焓热化学非平衡流动、局部热力学平衡（LTE）等离子体、电感耦合等离子体（ICP）、磁流体动力学（MHD，含多流体）、Maxwell 电磁场、辐射传输、固体传热与结构力学等多个领域；
- **数值层面**，在同一框架内并列支持有限体积（FVM）、残差分布法（RDS/FluctSplit）、间断伽辽金（DG）、通量重构（FR/CPR）、谱差分（SD）、谱体积（SV）、有限元（FE）等多种离散方法；
- **计算层面**，原生支持 MPI 大规模并行，并提供 CUDA GPU 加速路径。

这种"一框架、多物理、多方法"的形态，使 COOLFluiD 特别适合**方法学研究、物理模型对比与跨学科耦合问题**（如再入气动热环境中"流动 + 化学 + 辐射 + 壁面催化"的全链条仿真）。

### 1.1.2 全称与含义

COOLFluiD 的全称是：

> **CO**mputational **O**bject-**O**riented **L**ibraries for **Fluid D**ynamics

即"面向流体力学的计算型面向对象库集合"。缩写拆解：**COOL** = Computational Object-Oriented Libraries，**FluiD** = Fluid Dynamics；代码与文档中常以 **CF** 指代本软件（如 `CFcase`、`CFmesh`、`CFLog`、命名空间 `COOLFluiD`）。

> **准确性说明**：该全称是社区与官网沿用的标准展开。**本仓库 `README.md` 并未逐字写出这一展开**，仅将软件描述为 "The object-oriented HPC platform for CFD, plasma and multi-physics simulations"（`README.md` 第 2 行附近）。两种表述不矛盾，但引用出处时请以官网为准，勿称"见本仓库 README"。

尽管名称聚焦"流体动力学"，它的设计目标从一开始就是一个**通用的 PDE（偏微分方程）求解框架**——流体只是其上最成熟的一组应用。这一背景解释了代码中大量与具体物理无关的抽象层（`PhysicalModel`、`SpaceMethod`、`ConvergenceMethod`、`LinearSystemSolver` 等接口，见第 2 章）：**求解的"对象"是偏微分方程组，而不是"流体"本身**。

### 1.1.3 核心理念

COOLFluiD 的架构建立在三条原则之上（技术实现详见第 2 章）：

1. **内核—插件分离**。内核（`src/`）只负责仿真生命周期、网格数据结构、配置系统、并行通信与工厂机制，**不含任何具体物理或数值格式**；所有物理模型与数值方法都是插件（`plugins/`，实测 135 个目录，编译为独立动态库）。
2. **运行时动态组装**。一次仿真的"能力组合"由输入文件（CFcase）中的模块声明决定，例如：

   ```
   Simulator.Modules.Libs = libCFmeshFileReader libNavierStokes libFiniteVolume \
                            libNewtonMethod libFiniteVolumeNavierStokes libPetscI
   ```

   求解器启动时按需加载这些动态库并注册到工厂；同一份代码无需重编译即可切换"物理 × 方法 × 时间推进 × 线性求解器"的任意组合。
3. **多物理场可插拔耦合**。复杂问题被拆分为若干子系统（SubSystem，如流体、结构、辐射），由 `Maestro` 编排、经耦合器（`SubSystemCoupler`/`ConcurrentCoupler`）交换界面数据，从而以"积木"方式组装流固耦合、流—辐射耦合等应用。

> **提示**：理解了这三条原则，就理解了本手册的章节划分逻辑——第 2 章讲"框架如何运转"，第 3–4 章讲"插件提供什么"，第 6 章逐一盘点插件，第 11 章教你写自己的插件。

## 1.2 发展历史

### 1.2.1 起源：冯·卡门研究所（VKI），2002 年

COOLFluiD 于 **2002 年**在比利时**冯·卡门流体动力学研究所**（von Karman Institute for Fluid Dynamics，VKI，www.vki.ac.be）启动开发。VKI 在高超声速、气动热与等离子体实验/数值研究方面的传统，直接塑造了项目的技术取向——这也是 COOLFluiD 至今在高焓非平衡流动方向积淀最深的原因（见 1.4.1 节）。早期开发在欧盟 COCONUT 项目框架内进行，当时的用户手册 `doc/Manuals/COCONUT_user_manual.pdf` 保留了第一代内核的记录。项目主要作者 Andrea Lani 的博士论文 `doc/thesis/thesis_LANI.pdf` 系统阐述了其面向对象并行求解框架设计，是理解设计动机的一手文献（详见第 12.12 节参考文献）。

### 1.2.2 与 KU Leuven CmPA 的合作：MHD 方向的深化

自项目早期起，VKI 与**鲁汶大学（KU Leuven）数学等离子体天体物理中心**（Centre for mathematical Plasma Astrophysics，CmPA，https://wis.kuleuven.be/CmPA）长期合作，将 COOLFluiD 扩展到磁流体动力学与空间等离子体模拟。这一合作催生了 `MHD`、`MultiFluidMHD`、`FiniteVolumeMHD`、`FiniteVolumeMultiFluidMHD`、`FluxReconstructionMHD` 等成体系的插件群（合计数千个源文件与数百个验证算例，含 COCONUT 日冕/太阳风算例群），使 COOLFluiD 成为少有的同时覆盖"高焓气体动力学"与"计算磁流体"两个方向的开源平台。

### 1.2.3 版本沿革

| 阶段 | 说明 | 本仓库中的痕迹 |
|------|------|----------------|
| Kernel 1.x 时代 | COCONUT 项目时期的第一代内核 | `doc/Manuals/COCONUT_user_manual.pdf` |
| Kernel 2.x 重构 | 引入新的配置系统（`Config`）、数据套接字（DataSocket）、工厂/Provider 体系；本手册所述即此代 | 源码 `src/` 整体架构（第 2 章） |
| **2013.9（当前）** | COOLFluiD 发布版本号 2013.9；内核版本 2.5.0 | `CMakeLists.txt`：`COOLFLUID_VERSION 2013.9`、`CF_KERNEL_VERSION 2.5.0` |

当前代码库包含完整内核与实测 **135 个插件目录**（`plugins/`），覆盖物理模型、数值方法、时间推进、线性求解器、网格 IO/转换、动网格、耦合与后处理等全部类别（分类总表见第 6.1 节）。另请注意：开源社区存在基于新内核的演进分支，其 API 与本手册所述不兼容；使用上游新版本时请以其官方文档为准，本手册仅覆盖本仓库所载的 2013.9 代码。

### 1.2.4 开源协议：LGPL v3

COOLFluiD 以 **GNU 宽通用公共许可证第 3 版（LGPL v3）** 发布（见根目录 `LICENSE`，完整文本 `doc/lgpl.txt` 与 `doc/gpl.txt`）。对使用者的实际含义：

- **使用与再分发**：可自由使用、修改、再分发 COOLFluiD 本身，但分发修改后的库文件时须遵循 LGPL（提供源码或可重新链接的目标文件）；
- **专有插件**：LGPL 允许**动态链接**本库的第三方代码不强制开源——这为以插件形式开发内部专用物理模型（如自定义反应动力学库）留出了合法空间；
- **引用义务**：分发基于 COOLFluiD 的成果时，应保留原版权声明；学术成果发表时请引用相关论文（第 12.3 节）。

> **警告**：部分**可选外部依赖**的许可比 LGPL 严格（如商业线性求解器 Pardiso、SAMG），启用相应插件前请自行确认许可合规性（依赖清单见第 8.1 节）。

### 1.3.1 物理覆盖

### 1.3.2 数值覆盖

| 离散方法 | 核心插件 | 特点 |
|----------|----------|------|
| 单元中心有限体积（FVMCC） | `FiniteVolume` | 框架内最成熟的基线方法；二阶重构 + 各类限制器 |
| 残差分布法（RDS/FluctSplit） | `FluctSplit` | LDA、N、LDA-PSI、FCT 等分布格式；节点中心 |
| 间断伽辽金（DG） | `DiscontGalerkin` | 高阶、局部守恒 |
| 通量重构（FR/CPR） | `FluxReconstructionMethod` 族 | 多项式阶 P0–P10；VCJH 能量稳定修正函数族（参数可退化为 SD/CU/HU 特例）；与 DG 的等价性 |
| 谱差分（SD）/ 谱体积（SV） | `SpectralFD` 族、`SpectralFV` 族 | 基于 FR 框架的 `BasePointDistribution` 点分布 |

> **深入阅读**：上表每种方法的离散原理、通量格式、重构与限制器、时间推进与线性求解的完整推导与源码对照，见第 4 章（4.2 FVM、4.9 RDS、4.10 FR、4.11 SD/SV/DG/FE）；方法选型决策树见第 3.5.8 节。若你只想查"某个格式在 CFcase 里叫什么名字"，直接看第 4.17 节配置速查表。

### 1.3.3 计算能力

- **并行**：MPI 原生并行（内核 `PE` 封装），ParMetis 负载平衡（`ParMetisBalancer` 插件 + 内核 `DynamicBalancerMethod`）；Ghost 单元/虚拟态机制对用户透明；并行 I/O；
- **GPU**：CUDA 加速插件（`FiniteVolumeCUDA`、`FluxReconstructionCUDA`）与 ViennaCL 选项（混合 MPI/CUDA）；`Paralution` 迭代求解器 GPU 后端；
- **时间推进**：显式（Euler、多级 RK、低存储 RK）与隐式（BackwardEuler、Newton、LU-SGS）全谱系，支持 CFL 分段函数、双时间步；
- **线性求解**：PETSc（KSP/PC 全配置）、Pardiso、Trilinos、SAMG 代数多重网格、Paralution；
- **网格能力**：CFmesh 原生格式 + Gmsh/Gambit/CGNS/Tecplot/FAST/THOR 转换器；全局自适应加密（误差估计器驱动）、单元细化（`CFmeshCellSplitter`）、拉伸（`CFmeshExtruder`）；动网格（刚体运动、Laplacian 光顺、弹簧类比、FEM 变形）；
- **耦合**：子系统串行/并发耦合、流—辐射—固多场迭代框架。

### 1.3.4 代码规模速览

以本仓库 2013.9 快照计（统计口径：`find src plugins apps` 实测）：

- 内核 `src/`：1186 个文件（`Common/Config/Environment/Framework/MathTools/ShapeFunctions` 六大模块 + `logcpp` + `UnitTests`）；
- 插件 `plugins/`：9747 个文件（135 个插件目录；源码 + 1019 个 `.CFcase` 算例 + 751 个压缩网格/数据包）；
- 全部 C++ 源码：`.hh` 3977 个、`.cxx` 3347 个（合计 7324 个）；**原始总行数约 133 万行**（`src/` 约 15 万、`plugins/` 约 118 万），去除注释与空行后约 **71.6 万行**（本仓库实测 `find src plugins apps -name '*.hh' -o -name '*.cxx' | xargs cat | wc -l`）；
- 交付物：主求解器 `coolfluid-solver` 及工具类可执行程序（结构网格转换 `ConvertStructMesh`、Tecplot 文件合并 `tecplot_merge`、气动系数合并 `coef_merge`、CFcase 格式转换 `xcfcase_converter` 等，由 `CF_ADD_PLUGIN_APP` 宏构建）。

## 1.4 适用领域

下表给出"领域 → 典型插件组合 → 代表算例"的索引，具体算例说明见第 7 章对应小节。

| 领域 | 典型插件组合 | 代表算例（`plugins/…/testcases/`） |
|------|--------------|-------------------------------------|
| 高超声速/高焓 | NEQ + FiniteVolumeNEQ + Mutation\*（+ RadiativeTransfer、Catalycity） | `NavierStokes/DoubleEllipse`、`NEQ/TCNEQ/FireII`、`NavierStokes/BluntBody2D` |
| ICP/电弧风洞 | ICP/ArcJet + FiniteVolumeICP/ArcJet | `ICP/`（45 例）、`ArcJet/`（15 例） |
| MHD/空间等离子体 | MHD/MultiFluidMHD + FiniteVolumeMultiFluidMHD | `MultiFluidMHD/testcases/1_HartmannFlow`、`11_BrioWuTube`、`6_OrszagTang` |
| 气动声学 | LinEuler、LinearAdvSys | `NavierStokes/AccPulse`（FR/SD/SV 声脉冲族） |
| 湍流/LES | SA、KOmega、GReKO、LESvki | `SA/`、`GReKO/`、`NavierStokes/Cylinder`（LES Re=3900） |
| 传热/流固耦合 | Heat、StructMech、SubSystemCoupler | `Heat/`（28 例）、`SubSystemCoupler/`（35 例） |

### 1.4.1 高超声速与高焓流动

COOLFluiD 最具辨识度的能力所在。完整链条覆盖：**化学非平衡（CNEQ）→ 热化学非平衡（TCNEQ 两温度）→ 多振动温度与电子温度模型（Multi-Tv-Te）**，配合离解/电离反应动力学（Mutation 系列库、air-5/air-11 组分、Park 反应集）、壁面催化、有限速率表面过程，以及与流场迭代的辐射传输（HSNB/PARADE 谱带）。变量集体系（`Rhoivt`、`RhoivtTv` 等）与解析 Jacobian 为刚性源项的隐式求解提供了收敛性保障。经典验证包括 Fire II 再入（飞行试验热流对标）、双椭球 HEG 条件、钝体激波层等。逐项能力评估见 `doc/COOLFluiD_高焓高超声速求解能力评估报告.md`，算例与对标数据见第 7.2 节。

### 1.4.2 稀薄与等离子体流动（ICP/电弧风洞）

面向高焓风洞模拟：电感耦合等离子体炬（ICP）的电磁—流动耦合求解、弧加热器流动（ArcJet）、ATD 电弧热等离子体物性（`ATDModel`）、LTE 物性库与平衡组分表（Mutation 2.0 数据文件：26 种混合气、27 种平衡组分）。可用于风洞流场校测、来流条件生成与试验数据分析。

### 1.4.3 磁流体动力学与多流体等离子体

理想/电阻 MHD 的守恒型与投影型变量集、多流体（电子—离子—中性）模型、界面条件与电磁源项；配合 Maxwell 求解器可处理电磁感应问题。天体物理应用（日冕/太阳风 COCONUT 算例群、色球波、磁重联）与工程应用（磁控再入）均有自带算例。

### 1.4.4 气动声学与线性化流动

线化 Euler 方程（LinEuler）支持声脉冲、声涡输运等 CAA 基准；AccPulse 算例群以同一问题横向对比 FVM/FR/SD/SV 四类方法的色散—耗散特性，是方法选型的直接参考。

### 1.4.5 LES 与湍流基础研究

SA、k-ω 族、γ-Reθ 转换（GReKO）、γ-θ 转换（GammaAlpha）等 RANS 模型，以及多亚格子模型 LES 与统计后处理（`LESDataProcessing`：平均/脉动/能谱）；圆柱 LES Re=3900 等经典构型可直接复现。

### 1.4.6 传热、结构与多场耦合

稳态/瞬态导热、线弹性结构、热—力耦合，以及经耦合器组织的流—固共轭传热与流—辐射耦合（NEQ 源项中 `omegRad` 交换）。适合再入热防护、燃烧室壁等"多介质交界"问题。

## 1.5 与其他 CFD 软件的对比

### 1.5.1 对比维度

选型时建议从六个维度综合权衡：**物理模型广度**、**数值方法多样性**、**二次开发难度**、**并行/GPU 支持**、**社区与文档**、**许可证与获取门槛**。下表的对比以公开资料与社区普遍认知为依据，仅供选型参考；具体版本能力请以各软件官方文档为准。

### 1.5.2 对比对象

| 软件 | 许可 | 方法 | 强项 | 与 COOLFluiD 的相对位置 |
|------|------|------|------|--------------------------|
| OpenFOAM | GPL | FVM（不可压/可压通用） | 生态庞大、案例丰富、改造门槛低 | 物理覆盖广但离散方法单一；高焓非平衡/辐射/MHD 需自行拼装 |
| SU2 | LGPL | FVM + 连续伴随 | 外形优化与伴随敏感度 | 优化工作流成熟；多物理场以共轭传热/化学反应为主，无 MHD/ICP |
| FUN3D（NASA） | 受限分发 | 节点中心 FVM | 航空航天工程成熟度、非平衡能力 | 能力接近但非开源，二次开发受限 |
| Nektar++ / PyFR | 开源 | 谱元 / FR（GPU） | 高阶精度与 GPU 吞吐 | 高阶方法专精；多物理场与耦合远窄于 COOLFluiD |
| PLUTO / Athena++ | 开源 | FVM（天体 MHD） | 天体物理 MHD 基准 | 专注单一流体 MHD；无工程边界条件/结构耦合体系 |
| Fluent / STAR-CCM+ | 商业 | FVM | 工业流程、GUI、支持 | 工程效率高；方法黑箱，无法做格式级研究或新增方程 |

### 1.5.3 COOLFluiD 的差异化优势

1. **同一框架内多方法共存且可横向对比**：FVM/RDS/DG/FR/SD/SV 共用同一套网格、边界条件与 IO，做方法学论文或格式对比时无需多套软件换算口径（AccPulse 收敛族即是现成范例）。
2. **高焓非平衡链条完整**：NEQ（含 Multi-Tv-Te）+ Mutation 物理化学库 + 催化 + 辐射耦合在同一数据流内完成，开源软件中少见。
3. **MHD 多流体能力**：双流体/多组分等离子体模型带完整算例库，多数开源 CFD 完全不具备。
4. **插件式二次开发路径清晰**：Provider/工厂机制 + 骨架插件（`EmptySpaceMethod`）+ 源码树外开发选项（`CF_EXTRA_SEARCH_DIRS`），新增一个格式或模型的改动面可控（第 11 章）。

### 1.5.4 劣势与注意点

1. **文档分散且部分陈旧**：`doc/Manuals/` 各专题手册版本不一，本手册（第 0.4 节）给出了整合索引；
2. **构建依赖偏老**：CMake ≥ 2.8.3、Boost ≥ 1.42 的年代设定，在新系统上常需小规模适配（第 8 章 8.6 节给出已知问题清单）；
3. **版本分支认知成本**：Kernel 2（本手册）与社区演进分支 API 不兼容，引用网上资料时注意甄别；
4. **性能调优门槛**：默认配置面向正确性，大规模生产运行需按第 4.5–4.10 节与第 9 章调参（隐式策略、剖分均衡、IO 频率等）；
5. **交互体验朴素**：无 GUI 前处理/后处理，全流程基于文本 CFcase 与第三方可视化工具（第 10 章）。

> **提示**：若你的需求落在"高焓非平衡/等离子体/MHD + 方法学研究"交叉区，COOLFluiD 大概率是最合适的开源起点；若只是标准外形的标准气动计算，工程效率上商业软件或 OpenFOAM 更省力。
